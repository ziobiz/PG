ICOPAY 統合 Checkout API — 連携フローとエンドポイント

仕様 ID: ICOPAY-CHECKOUT-FLOW-001 · v1.0 · PG非依存インライン決済（ChillPay/JPAY 自動振分）

関連: Prepare API パラメータ表 · merchant-api-samples 一覧

1. 「統合」checkout とは

レガシー連携では PG ごとに prepare パスが分かれていました。統合 APIは prepare を 1 本にまとめ、 ICOPAY が加盟店の 運用 WEB PG 設定を読み取り、内部で ChillPay または JPAY に振り分けます。

integrationModeINLINE_UNIFIED
PreparePOST {publicApiBaseUrl}/api/middleware/v1/merchant/checkout/prepare
Embed スクリプト{publicApiBaseUrl}/v1/embed-checkout/{compId}

compId 例: 6000000028（本社 API 配信時に加盟店ごとに付与）

3. 推奨連携フロー

[加盟店サーバー] 注文(PENDING) 保存 │ ▼ [加盟店サーバー] POST .../checkout/prepare (buyer 必須、broker secret) │ ▼ [加盟店サーバー] data.sessionToken 取得 │ ▼ [ブラウザ] embed スクリプト + data-session-token 埋め込み │ ├─► GET /v1/embed-checkout/{compId} ├─► GET .../checkout/session?token=... (ウィジェット自動) └─► iframe → /pay/{compId} または /jpay-pay/{compId} │ ▼ [ブラウザ] postMessage ICOPAY_INLINE_CHECKOUT │ ▼ [加盟店サーバー] Webhook および/または GET .../checkout/status → 注文更新（冪等）
  1. 加盟店サーバー: POST .../merchant/checkout/prepare（buyer.email・phone・countryIso2 必須）
  2. 応答 data.sessionToken → ブラウザへ /v1/embed-checkout/{compId} スクリプトのみ渡す
  3. Webhook（merchantNotifyUrls）および/または GET .../checkout/status で PAID 確認

4. Prepare — 決済セッション作成

POST https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/prepare

ヘッダー

  • Content-Type: application/json
  • Accept: application/json
  • X-Icopay-Merchant-Broker-Secret: {brokerSecret}（ブローカーシークレット強制時）

必須 body

  • compId（または merchantId）、orderNo、amount
  • buyer.email、buyer.phone、buyer.countryIso2（ISO 3166-1 alpha-2）

応答の主要フィールド

  • sessionToken — embed の data-session-token に渡す
  • pgVendor — 運用 PG（例: JPAY、CHILLPAY）
  • embedScriptUrl — /v1/embed-checkout/{compId}
  • expiresAt — セッション有効期限

サンプル: unified-prepare-request.json、 unified-prepare-response.example.json

5. Session — トークン検証と PG 振分

GET https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/session?token={sessionToken}

embed ウィジェット（icopay-embed-checkout-widget.js）がブラウザで自動呼び出しします。加盟店サーバーから直接呼ぶ必要はほぼありません。 ブローカーシークレット不要 — トークンが一回限りの資格情報です。

pgVendoriframe パス
JPAY 系/jpay-pay/{compId}?entry=merchant_api&embed=1&session=...
ChillPay 系/pay/{compId}?entry=merchant_api&embed=1&session=...

6. Status — 決済状態照会

GET https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/status?compId=6000000028&orderNo={orderNo}

加盟店 サーバー 専用。postMessage・Webhook 後のサーバー側再確認に使用します。

応答: found、paymentStatus（例: PAID、NOT_FOUND）、approvalNo、amount、paidAt

7. Embed スクリプト — 決済画面の埋め込み

https://api.icopay.co.kr/v1/embed-checkout/6000000028

<div id="icopay-checkout"></div>
<script src="https://api.icopay.co.kr/v1/embed-checkout/6000000028"
        data-session-token="{prepare 応答の sessionToken}"
        data-target="icopay-checkout"
        data-lang="JPN"
        async defer charset="utf-8"></script>
<script src="https://api.icopay.co.kr/merchant-api-samples/common/icopay-checkout.js"></script>
<script>
  IcopayCheckout.onMessage(function (detail) {
    if (detail.phase === 'finished' && detail.success) {
      location.href = '/order-complete?orderNo=' + encodeURIComponent(detail.orderNo || '');
    }
  }, 'https://api.icopay.co.kr');
</script>

決済完了時、iframe が window.postMessage で ICOPAY_INLINE_CHECKOUT イベントを送信します。

8. セキュリティチェックリスト

  • X-Icopay-Merchant-Broker-Secret は加盟店 サーバー のみ — ブラウザ・アプリに露出しない
  • sessionToken はブラウザのみに渡し、expiresAt 前に使用
  • prepare 前に注文を PENDING で保存、Webhook/status 処理は 冪等に
  • Webhook URL は本社登録時 HTTPS 推奨（merchantNotifyUrls）

9. FAQ

Session をサーバーから呼ぶ必要はありますか？ いいえ。embed ウィジェットがブラウザで呼び出します。

ChillPay 加盟店なのに JPAY が開くことはありますか？ 統合 API は本社設定の 運用 WEB PG に従って振分けます。

postMessage だけで十分ですか？ UX には足りる場合がありますが、サーバー確定は Webhook または status 照会を推奨します。
