ICOPAY 통합 Checkout API — 연동 흐름 및 엔드포인트

문서 ID: ICOPAY-CHECKOUT-FLOW-001 · v1.0 · PG 무관 인라인 결제 (ChillPay/JPAY 자동 분기)

관련: Prepare API 파라미터 표 · merchant-api-samples 목록

1. “통합” checkout이란?

레거시 연동은 PG별로 prepare 경로가 분리되어 있었습니다. 통합 API는 하나의 prepare만 호출하면 ICOPAY가 가맹점의 운영 WEB PG 설정을 읽고 ChillPay 또는 JPAY로 내부 위임합니다.

integrationModeINLINE_UNIFIED
PreparePOST {publicApiBaseUrl}/api/middleware/v1/merchant/checkout/prepare
Embed 스크립트{publicApiBaseUrl}/v1/embed-checkout/{compId}

compId 예: 6000000028 (본사 API 배포 시 가맹점별 할당)

3. 권장 연동 흐름

[가맹 서버] 주문(PENDING) 저장 │ ▼ [가맹 서버] POST .../checkout/prepare (buyer 필수, broker secret) │ ▼ [가맹 서버] data.sessionToken 확보 │ ▼ [브라우저] embed 스크립트 + data-session-token 삽입 │ ├─► GET /v1/embed-checkout/{compId} ├─► GET .../checkout/session?token=... (위젯 자동 호출) └─► iframe → /pay/{compId} 또는 /jpay-pay/{compId} │ ▼ [브라우저] postMessage ICOPAY_INLINE_CHECKOUT │ ▼ [가맹 서버] 웹훅 및/또는 GET .../checkout/status → 주문 갱신 (멱등)
  1. 가맹 서버: POST .../merchant/checkout/prepare (buyer.email, phone, countryIso2 필수)
  2. 응답 data.sessionToken → 브라우저에 /v1/embed-checkout/{compId} 스크립트만 전달
  3. 웹훅(merchantNotifyUrls) 및/또는 GET .../checkout/status로 PAID 확인

4. Prepare — 결제 세션 생성

POST https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/prepare

헤더

  • Content-Type: application/json
  • Accept: application/json
  • X-Icopay-Merchant-Broker-Secret: {brokerSecret} (브로커 시크릿 강제 시)

필수 body

  • compId (또는 merchantId), orderNo, amount
  • buyer.email, buyer.phone, buyer.countryIso2 (ISO 3166-1 alpha-2)

응답 핵심 필드

  • sessionToken — embed data-session-token에 전달
  • pgVendor — 운영 PG (예: JPAY, CHILLPAY)
  • embedScriptUrl — /v1/embed-checkout/{compId}
  • expiresAt — 세션 만료 시각

샘플: unified-prepare-request.json, unified-prepare-response.example.json

5. Session — 세션 검증 및 PG 분기

GET https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/session?token={sessionToken}

embed 위젯(icopay-embed-checkout-widget.js)이 브라우저에서 자동 호출합니다. 가맹 서버에서 직접 호출할 필요는 거의 없습니다. 브로커 시크릿 불필요 — 토큰이 일회용 자격 증명입니다.

pgVendoriframe 경로
JPAY 계열/jpay-pay/{compId}?entry=merchant_api&embed=1&session=...
ChillPay 계열/pay/{compId}?entry=merchant_api&embed=1&session=...

6. Status — 결제 상태 조회

GET https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/status?compId=6000000028&orderNo={orderNo}

가맹 서버 전용. postMessage·웹훅 이후 서버 측 재확인에 사용합니다.

응답: found, paymentStatus (예: PAID, NOT_FOUND), approvalNo, amount, paidAt

7. Embed 스크립트 — 결제창 삽입

https://api.icopay.co.kr/v1/embed-checkout/6000000028

<div id="icopay-checkout"></div>
<script src="https://api.icopay.co.kr/v1/embed-checkout/6000000028"
        data-session-token="{prepare 응답 sessionToken}"
        data-target="icopay-checkout"
        data-lang="KOR"
        async defer charset="utf-8"></script>
<script src="https://api.icopay.co.kr/merchant-api-samples/common/icopay-checkout.js"></script>
<script>
  IcopayCheckout.onMessage(function (detail) {
    if (detail.phase === 'finished' && detail.success) {
      location.href = '/order-complete?orderNo=' + encodeURIComponent(detail.orderNo || '');
    }
  }, 'https://api.icopay.co.kr');
</script>

결제 완료 시 iframe이 window.postMessage로 ICOPAY_INLINE_CHECKOUT 이벤트를 보냅니다.

8. 보안 체크리스트

  • X-Icopay-Merchant-Broker-Secret은 가맹 서버에만 보관 — 브라우저·앱에 노출 금지
  • sessionToken은 브라우저에만 전달, expiresAt 이전에 사용
  • prepare 전 주문을 PENDING으로 저장, 웹훅/status 처리는 멱등하게
  • 웹훅 URL은 본사 등록 시 HTTPS 권장 (merchantNotifyUrls)

9. FAQ

Session을 서버에서 호출해야 하나요? 아니요. embed 위젯이 브라우저에서 호출합니다.

ChillPay 가맹인데 JPAY가 열릴 수 있나요? 통합 API는 본사에 설정된 운영 WEB PG 기준으로 분기합니다.

postMessage만으로 충분한가요? UX에는 충분할 수 있으나, 서버 확정은 웹훅 또는 status 조회를 권장합니다.
