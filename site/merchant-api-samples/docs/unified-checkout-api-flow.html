ICOPAY Unified Checkout API — Integration Flow & Endpoints

Spec ID: ICOPAY-CHECKOUT-FLOW-001 · v1.0 · PG-agnostic inline checkout (ChillPay/JPAY auto-routing)

Related: Prepare API parameter tables · merchant-api-samples index

1. What is “unified” checkout?

Legacy integrations used separate prepare paths per PG (ChillPay, JPAY). The unified API exposes one prepare endpoint; ICOPAY reads the merchant’s operational WEB PG setting and routes internally to ChillPay or JPAY.

integrationModeINLINE_UNIFIED
PreparePOST {publicApiBaseUrl}/api/middleware/v1/merchant/checkout/prepare
Embed script{publicApiBaseUrl}/v1/embed-checkout/{compId}

Example compId: 6000000028 (assigned per merchant at HQ deployment).

3. Recommended flow

[Merchant server] Save order (PENDING) │ ▼ [Merchant server] POST .../checkout/prepare (buyer required, broker secret) │ ▼ [Merchant server] Receive data.sessionToken │ ▼ [Browser] Embed script + data-session-token on checkout page │ ├─► GET /v1/embed-checkout/{compId} ├─► GET .../checkout/session?token=... (widget, automatic) └─► iframe → /pay/{compId} or /jpay-pay/{compId} │ ▼ [Browser] postMessage ICOPAY_INLINE_CHECKOUT │ ▼ [Merchant server] Webhook and/or GET .../checkout/status → update order (idempotent)
  1. Merchant server: POST .../merchant/checkout/prepare (buyer.email, phone, countryIso2 required)
  2. Pass data.sessionToken to the browser → load /v1/embed-checkout/{compId} only
  3. Confirm PAID via webhook (merchantNotifyUrls) and/or GET .../checkout/status

4. Prepare — create payment session

POST https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/prepare

Headers

  • Content-Type: application/json
  • Accept: application/json
  • X-Icopay-Merchant-Broker-Secret: {brokerSecret} (when enforce is on)

Required body fields

  • compId (or merchantId), orderNo, amount
  • buyer.email, buyer.phone, buyer.countryIso2 (ISO 3166-1 alpha-2)

Key response fields

  • sessionToken — pass to embed data-session-token
  • pgVendor — operational PG (e.g. JPAY, CHILLPAY)
  • embedScriptUrl — /v1/embed-checkout/{compId}
  • expiresAt — session expiry

Samples: unified-prepare-request.json, unified-prepare-response.example.json

5. Session — validate token & route PG

GET https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/session?token={sessionToken}

Called automatically by the embed widget (icopay-embed-checkout-widget.js). Merchants rarely call this from the server. No broker secret — the token is a one-time credential.

pgVendoriframe path
JPAY family/jpay-pay/{compId}?entry=merchant_api&embed=1&session=...
ChillPay family/pay/{compId}?entry=merchant_api&embed=1&session=...

6. Status — query payment result

GET https://api.icopay.co.kr/api/middleware/v1/merchant/checkout/status?compId=6000000028&orderNo={orderNo}

Merchant server only. Use for server-side confirmation after postMessage or webhook.

Response includes found, paymentStatus (e.g. PAID, NOT_FOUND), approvalNo, amount, paidAt.

7. Embed script — mount checkout iframe

https://api.icopay.co.kr/v1/embed-checkout/6000000028

<div id="icopay-checkout"></div>
<script src="https://api.icopay.co.kr/v1/embed-checkout/6000000028"
        data-session-token="{sessionToken from prepare}"
        data-target="icopay-checkout"
        data-lang="ENG"
        async defer charset="utf-8"></script>
<script src="https://api.icopay.co.kr/merchant-api-samples/common/icopay-checkout.js"></script>
<script>
  IcopayCheckout.onMessage(function (detail) {
    if (detail.phase === 'finished' && detail.success) {
      location.href = '/order-complete?orderNo=' + encodeURIComponent(detail.orderNo || '');
    }
  }, 'https://api.icopay.co.kr');
</script>

On completion the iframe posts ICOPAY_INLINE_CHECKOUT via window.postMessage.

8. Security checklist

  • Keep X-Icopay-Merchant-Broker-Secret on the merchant server only — never in browser or mobile apps.
  • Pass sessionToken to the browser only; use before expiresAt.
  • Create orders as PENDING before prepare; finalize with idempotent webhook/status handling.
  • Register HTTPS webhook URLs via HQ (merchantNotifyUrls).

9. FAQ

Do I call Session from my server? No — the embed widget calls it in the browser.

Can JPAY open for a “ChillPay” merchant? Unified routing follows the operational WEB PG configured at HQ, not the legacy per-PG API path.

Is postMessage enough? Use it for UX; confirm payment on the server via webhook and/or status.
