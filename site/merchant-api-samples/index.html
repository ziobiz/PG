ICOPAY Merchant Integration Samples

Download base: {publicApiBaseUrl}/merchant-api-samples/

Use together with the HQ deployment kit JSON keys integrationModes.json and integrationModes.php.

① JSON (direct REST)

  1. Integration flow & endpoints (Prepare · Session · Status · Embed): EN · KO · JA · CH · TH
  2. Prepare API parameter tables (Tables 1.1 & 1.2): EN · KO · JA · CH · TH
  3. Crypto checkout API (payMeans=CRYPTO, Callback reuse): EN · KO · JA · CH · TH
  4. json/README.txt
  5. unified-prepare-request.json — prepare request body (card)
  6. crypto-prepare-request.json — prepare with payMeans=CRYPTO
  7. unified-prepare-response.example.json — live response example
  8. unified-prepare-sandbox-response.example.json — sandbox prepare (no payUrl; call complete)

Live: POST .../prepare → embed. Sandbox secret: data.sandbox===true → POST .../checkout/complete → Payments → Sandbox history (never open payUrl).

② PHP

  1. php/icopay_config.example.php → icopay_config.php (keep outside document root)
  2. php/IcopayMerchantApi.php — API client
  3. checkout_unified.php — integrated checkout (recommended)
  4. notify_webhook.php — webhook stub
  5. common/icopay-checkout.js — postMessage handler

Use only checkout_unified.php for new merchants. Payment-agency brand names are not part of the merchant contract.

JSP (Java 11+)

  1. jsp/icopay-config.example.properties
  2. jsp/IcopayMerchantApi.sample.java
  3. jsp/notify-webhook.jsp

Prefer PHP checkout_unified.php or JSON REST for new merchants.

Integration flow

Live: Create order → server prepare → sessionToken → /v1/embed-checkout/{compId} → Status/webhook

Sandbox: same prepare URL with the sandbox secret → sandbox=true → complete (no card window) → sandbox history
