# 배포 전 테스트·체크리스트

## 1. 로컬 (PC에서 반드시)

**JDK 17** (`JAVA_HOME` 설정 후):

```bat
cd pg-app
gradlew.bat test bootJar
```

- `BUILD SUCCESSFUL` 이고 `test` 가 통과해야 합니다.
- 스모크 테스트: `PgApiSmokeTest` — `GET /api/auth/me` 가 토큰 없이 **200 + JSON** 인지 확인합니다.

**수동 실행 (dev / H2):**

```bat
gradlew.bat bootRun --args="--spring.profiles.active=dev"
```

- 브라우저·curl: `http://127.0.0.1:8080/api/auth/me` → 예: `{"success":true,"data":{"ok":true}}`
- 관리자: `http://localhost:8080/login.html` (워크스페이스 URL 규칙 준수)

## 2. VPS (서버 SSH)

`pg-app` 기동 후:

```bash
curl -s http://127.0.0.1:8080/api/auth/me
# 또는
wget -qO- http://127.0.0.1:8080/api/auth/me
```

- **JSON** 이 나오면 앱은 정상입니다.
- **연결 거부**면 JAR·포트·프로세스를 먼저 확인합니다.

**스크립트:** `server-scripts/check-pg-endpoints.sh` (선택)

## 3. 공인 도메인 (`https://api.icopay.co.kr`)

- 여기서 **403 Forbidden (Apache 문구)** 가 나오면 **Origin 웹서버(Apache/Nginx)** 가 8080으로 넘기지 않는 상태입니다.
- 코드·JAR 만으로는 해결되지 않습니다.  
  → `server-config/apache-api-icopay-reverse-proxy.conf` 또는 `nginx-api-icopay.conf` 로 **전체 경로 프록시**를 맞춥니다.
- 상세: [api_403_진단_및_Apache설정.md](./api_403_진단_및_Apache설정.md)

## 4. 이번에 저장소에서 맞춘 것 (요약)

| 항목 | 내용 |
|------|------|
| 빌드 | `CompService.registerWithExtra` 인자 개수, `HqNotifyEnvService` Map 타입, `ApiComp`/`ApiHq` catch 순서 |
| API 406 | `WebMvcConfig` 의 `ignoreAcceptHeader`+기본 HTML 제거 (REST JSON 과 충돌) |
| 필터 | `ApiAcceptFilter` 서블릿 등록 (`ApiAcceptFilterConfig`) — 빈 Accept 보정 |
| 테스트 | `src/test/java/com/pg/PgApiSmokeTest.java` (`dev` 프로파일) |
| 점검 스크립트 | `server-scripts/check-pg-endpoints.sh` |

---

**결론:** 로컬·서버 8080까지는 **지금 절차로 “진행 도는지” 검증 가능**합니다. **공인 `api.icopay.co.kr` 는 웹서버(443) 설정이 끝나야** 완전히 통과합니다.
