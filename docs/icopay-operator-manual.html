📋 명명 원칙

ICOPAY는 단일 API 뒤에서 여러 결제대행사를 통합하는 플랫폼입니다. 본 매뉴얼의 통합 기능(체크아웃, URL결제, 통합거래 등)은 중립적인 ICOPAY 용어를 사용합니다. 「JPAY 전용」 표기는 JPAY에만 해당하는 기능에만 사용됩니다.

1. 관리자 메뉴 구조 및 역할별 접근

ICOPAY 관리자 사이트(https://icopay.co.kr) V2.0은 기능 허브 중심 메뉴 구조입니다. 총본사(슈퍼관리자)는 모든 메뉴에 접근 가능합니다.

🔑 총본사(슈퍼관리자)는 모든 메뉴에 접근 가능합니다.

2. 본사정책 — 수수료·리스크 총본사 전용

본사정책 > 수수료·리스크 허브

수수료·리스크 허브는 같은 화면 내 4개 탭(수수료, 대행수수료, 차지백, 리스크)으로 구성됩니다. 탭을 전환하면 해당 설정 영역이 나타납니다.

2-1. 수수료 탭

본사정책 > 수수료·리스크 > 수수료 탭

시스템 전체에 적용되는 기본 수수료 정책을 설정합니다. 가맹점별 개별 수수료가 없는 경우 이 값이 자동 적용됩니다.

설정 항목설명비고
결제 수단별 기본 수수료율신용카드, 직불카드, 지갑이체, QR코드 등 수단별 기본 %소수점 2자리까지
통화별 수수료 정책THB, USD, KRW, JPY 등 통화 단위별 기준 적용다중 통화 지원
수수료 적용 기준일변경 수수료가 시작되는 날짜 (과거일 설정 불가)즉시 또는 예약 적용
수수료 변경 이력변경 일시·담당자·변경 전후 값 기록 조회감사(Audit) 목적
①본사정책 > 수수료·리스크 허브 진입 → 수수료 탭 선택
②결제 수단별 기본 수수료율 입력 (예: 신용카드 2.5%, QR 1.8%)
③통화별 정책 적용 여부 확인
④적용 기준일 설정 → 저장

2-2. 대행수수료 탭

본사정책 > 수수료·리스크 > 대행수수료 탭

PG사 대행 수수료(ICOPAY가 PG사에 지불하는 원가 수수료)를 관리합니다.

설정 항목설명
PG사별 대행 수수료율각 결제대행사(PG코드)별 원가 수수료 % (Eximbay 등 신규 PG 포함)
통화별 대행 수수료거래 통화 단위별 대행 수수료 차등 적용
마진 계산 도구기본 수수료 - 대행수수료 = 순마진 자동 계산 표시

2-3. 차지백 탭

본사정책 > 수수료·리스크 > 차지백 탭

차지백(Chargeback) 발생 시 처리 정책 및 수수료를 설정합니다.

설정 항목설명
차지백 처리 수수료차지백 1건당 부과 수수료 금액
차지백 자동 승인 한도일정 금액 이하 차지백 자동 승인 처리 기준
차지백 분쟁 기간가맹점이 소명할 수 있는 기간 (일 단위)
차지백 알림 채널차지백 발생 시 통보 이메일·LINE 설정

2-4. 리스크 탭

본사정책 > 수수료·리스크 > 리스크 탭

이상 거래 감지 및 리스크 필터링 정책을 설정합니다.

설정 항목설명
일일 거래 한도가맹점별 일일 최대 결제 허용 금액
단건 거래 한도1회 결제 최대 허용 금액
속도 제한(Velocity)동일 카드/IP의 단위 시간당 결제 시도 횟수 제한
블랙리스트 관리차단할 카드번호, IP, 이메일 등록 및 관리
이상 거래 자동 차단설정 조건 초과 시 자동 거래 거절 여부
⚠ 리스크 필터 설정은 즉시 적용됩니다. 설정 변경 전 영향도를 충분히 검토하십시오.

3. 본사정책 — 결제·URL 총본사 전용

본사정책 > 결제·URL 허브

결제 라우팅, URL결제, 태블릿 UX 설정을 관리하는 허브입니다. 3개 탭으로 구성됩니다.

3-1. 결제 라우팅 탭

본사정책 > 결제·URL > 결제 라우팅 탭

카드별로 분리되어 있습니다: 결제 실행방식·경로 / 멀티 결제대행사 라우팅 / 결제창·카드인증 기본값 / WordPress·URL 재결제 / JPAY 포털·구독·통화 등.

설정 항목(카드)설명
결제 실행방식·경로API 중계·URL 결제별 INLINE/REDIRECT 기본값, 경로 템플릿, 채널 제공 여부
멀티 결제대행사 라우팅브랜드·통화 기준 멀티 PG 사용 여부 및 라우팅 방식
결제창·카드인증 기본값모바일 결제창·입력방식·카드인증(3DS/2DS). 가맹 「본사정책 따름」 시 적용. 구독 초회는 항상 3DS
WordPress·URL 재결제WordPress 플러그인 전역 on/off, 저장카드 재결제 URL 제공

3-2. URL결제 탭

본사정책 > 결제·URL > URL결제 탭
설정 항목설명
결제 URL 형식가맹점 결제 URL 패턴 설정 (경로 구조)
URL 유효기간생성된 결제 URL의 만료 시간 (분/시간)
URL 재사용 허용 여부동일 URL 복수 결제 허용 여부
단축 URL 설정결제 URL 단축 서비스 연동 여부

3-3. 태블릿 UX 탭

본사정책 > 결제·URL > 태블릿 UX 탭

태블릿(운영 모드)에서 조직 등급별로 노출할 메뉴를 체크박스로 선택합니다. 결제창 카드인증·입력방식 기본값은 결제 라우팅 탭에 있습니다.

설정 항목설명
태블릿 메뉴 매트릭스메뉴별·조직등급(총본사~가맹점)별 노출 여부. 체크된 메뉴만 태블릿 UI에 표시

4. 본사정책 — 노티 센터 총본사 전용

본사정책 > 노티 센터 허브

결제 완료 후 가맹점 서버로 전송되는 노티(Notify)의 구성, 필드 매핑, 수령 로그를 관리합니다.

4-1. 노티 구성 탭

본사정책 > 노티 센터 > 노티 구성 탭
설정 항목설명
노티 전송 방식HTTP POST (JSON) / Form 방식 선택
재시도 정책노티 실패 시 재시도 횟수 및 간격 (예: 3회, 5분 간격)
타임아웃 설정가맹점 서버 응답 대기 시간 (초)
서명(Signature) 방식HMAC-SHA256 서명 키 설정 및 검증 방법

4-2. 필드 매핑 탭

본사정책 > 노티 센터 > 필드 매핑 탭

노티 페이로드에 포함할 필드와 필드명을 커스터마이징합니다.

필드 그룹포함 가능 필드
결제 기본 정보order_id, amount, currency, status, paid_at
가맹점 정보merchant_id (ICOPAY 집계 MID만 — PG MID 미포함)
구매자 정보buyer_name, buyer_email, buyer_phone (선택)
결제 수단 정보payment_method, card_brand, card_last4
🔒 PG사 MID·API키는 노티 페이로드에 절대 포함되지 않습니다. ICOPAY 내부 식별 정보만 전송됩니다.

4-3. 수령 로그 탭

본사정책 > 노티 센터 > 수령 로그 탭
  • 가맹점별 노티 전송 이력 조회 (기간, 상태별 필터)
  • 성공/실패/재시도 상태 확인
  • 실패 노티 수동 재전송
  • 응답 HTTP 코드 및 응답 본문 확인

6. 본사정책 — 조직·화면 총본사 전용

본사정책 > 조직·화면 허브

15. FAQ — 자주 묻는 질문

V2.0에서 메뉴가 허브 구조로 바뀐 이유는 무엇인가요?
ICOPAY V2.0은 연관 기능(수수료·리스크, 결제·URL, 노티 센터 등)을 하나의 허브 화면에서 탭으로 관리하도록 개선했습니다. 기존 개별 메뉴는 각 허브 내 탭으로 이동되었으며, 화면·API·권한 키는 그대로 유지됩니다. 버전별 변경 내역은 본사정책 > 플랫폼 > 업데이트 내용 탭에서 확인할 수 있습니다.
이전 메뉴 이름(예: 수수료설정)은 어디에서 찾나요?
구 '수수료설정'은 '본사정책 > 수수료·리스크 허브 > 수수료 탭'으로 이동되었습니다. LEGACY 메뉴 표시가 필요하면 URL에 ?menu=legacy를 사용할 수 있습니다(운영 전환 기간 한정).
본사 계정인데 '본사정책' 메뉴가 보이지 않습니다.
'본사정책'과 '연동·배포' 메뉴는 총본사(슈퍼관리자) 전용입니다. 본사·총판 역할로는 해당 메뉴에 접근할 수 없습니다. 수수료·리스크 등 설정이 필요한 경우 총본사에 요청하십시오.
정산실행·정산배포 메뉴가 보이지 않습니다.
정산실행·정산배포·정산대기·통합정산은 총본사 전용 메뉴입니다. 본사·총판은 정산 결과 조회(가맹점정산, 수수료내역, 잔액내역 등)만 가능합니다.
노티 구성에서 재시도 정책을 변경했는데 즉시 적용되나요?
저장 후 즉시 적용됩니다. 단, 이미 실패하여 재시도 큐에 들어간 노티는 변경 전 정책으로 처리됩니다. 변경 후 신규 발생하는 실패 노티부터 새 정책이 적용됩니다.
PG사 연동 정보(MID, API키)가 가맹점에게 노출될 위험은 없나요?
전혀 없습니다. PG사 MID·API키는 ICOPAY 내부 서버에서만 사용되며, 가맹점 API 응답이나 노티 페이로드에는 절대 포함되지 않습니다. 가맹점에는 ICOPAY 집계 MID(order_id 기반)만 전달됩니다.
가맹 API 출시 위저드에서 발급한 API Key를 재발급해야 하는 경우는?
보안 사고 의심, 키 유출, 가맹점 요청 등의 경우 '연동·배포 > 가맹 API 출시 > ③키·문서' 탭에서 재발급할 수 있습니다. 재발급 즉시 기존 키는 무효화되므로, 가맹점 서버에 새 키를 즉시 적용해야 합니다.
리스크 탭에서 블랙리스트에 등록하면 해당 카드로는 모든 가맹점에서 결제가 차단되나요?
네, 시스템 전역 블랙리스트로 등록된 카드번호·IP는 ICOPAY를 통한 모든 가맹점 결제에서 자동 차단됩니다. 특정 가맹점에만 적용하는 개별 차단은 해당 가맹점 리스크 설정에서 별도로 등록하십시오.
