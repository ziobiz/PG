## 1. 개요

**리스크 필터**는 카드 결제 요청을 PG로 보내기 **전에** 비정상·의심 요청을 서버가 미리 차단하는 기능입니다. 같은 화면의 「리스크설정」은 **동일 카드 비성공 누적 → 대기·비활성 자동등록**이며, 상세는 통합 매뉴얼 §1을 참고하세요.

| 영역 | 성격 |
|------|------|
| **리스크설정(트리거)** | 동일 카드 비성공 누적 → 대기(1~4차)·비활성카드 자동등록 |
| **리스크 필터링** | PG 송부 **전** 사전 차단 + JPAY **사후** 고위험 반영 |
| **가맹점 리스크 현황** | 가맹점별 트리거 적용 방식·값 |

리스크 **필터링**은 **본사 단위 공통**입니다. 저장 즉시 적용됩니다(재배포 불필요).

### 1.1 적용 지점

| 구분 | 시점 | 대상 PG | 동작 |
|------|------|---------|------|
| **사전 필터(Presale)** | 결제 승인 API 호출 직전 | JPAY, ChillPay, Eximbay(평가 경로) | 조건 충족 시 **PG 호출 취소** |
| **사후 필터(Postsale)** | JPAY `pay_index` 응답 수신 후 | JPAY | 고위험·PY0124 시 **카드 쿨다운·현황 기록** |

> Eximbay 등 카드번호를 서버가 받지 않는 호스티드 흐름: 이메일·전화·성명·IP·이메일 속도는 적용, **카드 해시 기반**(카드 속도·연락처 불일치)은 skip.

## 3. 사전 필터 항목별 설명

### 3.0 사전필터 사용 (마스터 스위치)

- 항목: **사전필터 사용** (`presaleFilterEnabledYn`)
- **미사용**이면 아래 개별 사전 필터가 모두 OFF.
- JPAY 사후 쿨다운 항목은 이 스위치와 **독립**.

### 판정 순서

```
① 비정상 이메일 → ② 비정상 전화번호 → ③ 의심 holder명
→ ④ 카드 속도제한 → ⑤ 이메일 속도제한 → ⑥ IP 속도제한
→ ⑦ 구매자 연락처 불일치
```

### 3.1 비정상 이메일 (`filterEmailInvalidYn`)

- 기본 이메일 형식 위반, 로컬부 2자 미만, 동일문자 반복(3자+), 도메인 `example.*` / `test` / `test.*`
- 이메일 없으면 검사 안 함

### 3.2 비정상 전화번호 (`filterPhoneInvalidYn`)

- 숫자만 추출. 7미만·15초과, 동일숫자, 연속 증감 8자리+, `000000` 시작 / `0000000` 끝
- 전화 없으면 검사 안 함

### 3.3 의심 holder명 (`filterHolderNameYn`)

- 키워드(부분일치): `GIFTCARD HOLDER`, `GIFT CARD`, `PAYPAY USER`, `VPRECA`/`V PRECA`, `MERPAY MEMBER`, `KYASH MEMBER`, `PREPAID MEMBER`, `VANDALE USER`, `BUSINESS CARD`

### 3.4~3.6 속도 제한

- 카드 / 이메일 / IP — 각각 가맹 단위, 최근 **속도제한 창(분)** · **속도제한 횟수**
- 카드 속도는 PAN 해시가 있을 때만

### 3.7 구매자 연락처 불일치 (`filterBuyerContactMismatchYn`)

- 동일 카드 최근 1건과 이메일→전화→성명 비교. 성·이름 순서 바뀜은 동일.

> **자동기억:** **본사정책 → 결제·URL → 결제창 표시 기본값 → 자동기억**  
> (리스크 필터링 섹션이 아님. `HqApiConfig` 기본값.)

## 4. 속도 제한 값

| 항목 | 필드 | 기본값 | 설명 |
|------|------|--------|------|
| 속도제한 창(분) | `velocityWindowMinutes` | 10 | 1~1440 |
| 속도제한 횟수 | `velocityMaxAttempts` | 3 | 1~99 |

예) 창 10분 · 횟수 3 → 동일 키로 10분 안 3회 이상이면 차단.

## 5. JPAY 사후(Postsale) · 리스크 현황

| 항목 | 필드 | 판정 대상 |
|------|------|-----------|
| JPAY 사후 고위험 리스크현황 | `postsaleCooldownJpayHighriskYn` | HIGH-RISK/고위험 계열, 연락처 불일치 계열 |
| JPAY PY0124 리스크현황 | `postsaleCooldownJpayPy0124Yn` | `PY0124` · 거래 확인 불가 계열 |

- **사용**: 운영관리 → 리스크 현황에 사후 이벤트 기록  
- **미사용**: 리스크 현황 적재 생략  
- **위험관리**: 「위험관리 사용=Y」이면 JPAY 고위험·PY0124 FAIL 도 **항상** 쿨다운·자동 비활성 트리거에 포함(위 옵션과 무관)  

---

## 6. 차단 시 동작

1. PG 미호출  
2. 전산 대기 → **취소(20)**  
3. `tb_pay_risk_filter_event` → **운영관리 → 리스크 현황**  
4. 구매자 다국어 안내  
5. `errorCode=PRESALE_RISK_FILTER`, `filterCode=…`

| 코드 | 현황 표기 |
|------|-----------|
| `EMAIL_INVALID` | 비정상 이메일 |
| `PHONE_INVALID` | 비정상 전화번호 |
| `HOLDER_NAME_SUSPICIOUS` | 의심 holder명 |
| `VELOCITY_CARD` / `VELOCITY_EMAIL` / `VELOCITY_IP` | 속도 제한 |
| `BUYER_EMAIL_MISMATCH` / `BUYER_PHONE_MISMATCH` / `BUYER_NAME_MISMATCH` | 연락처 불일치 |
| `POSTSALE_JPAY_HIGH_RISK` / `POSTSALE_JPAY_PY0124` | 사후 분류 |

## 9. FAQ

- 정상 고객 차단 → 현황 `filterCode` 확인 후 창/횟수 완화 또는 항목 OFF  
- 일부만 OFF → 사전필터=사용 유지, 해당 항목만 미사용  
- 전부 OFF → 사전필터=미사용 (사후는 별도)  
- PG 로그 없음 → 사전 차단 정상  
- 호스티드 PG → 카드 기반 필터 skip
