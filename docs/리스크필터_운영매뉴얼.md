# 리스크 필터 운영 매뉴얼

> 대상: 총본사·본사·총판 운영자
> 화면: **본사설정 → 리스크설정**(`/hq/riskCardPolicy`)의 「리스크 필터링」 영역, **운영관리 → 리스크 현황**(`/risk/list`)
> 관련 저장소 코드: `PayPresaleRiskFilterService`, `PayPresaleRiskFilterCodes`, `PayPresaleRiskFilterI18n`, `HqRiskCardPolicy`, `OpsPayRiskFilterService`, `JpayPostSaleRiskCooldownService`

---

## 1. 개요

**리스크 필터**는 카드 결제 요청을 PG(**JPAY·ChillPay**)로 보내기 **전에** 비정상·의심 요청을 서버가 미리 차단하는 기능입니다. 「리스크설정」 화면은 세 영역으로 구성됩니다.

| 영역 | 성격 | 본 매뉴얼 |
|------|------|-----------|
| **리스크설정(트리거)** | 동일 카드 비성공 누적 → 대기(1~4차)·비활성카드 자동등록 | 참고(§7) |
| **리스크 필터링** | PG 송부 **전** 사전 차단 + JPAY **사후** 고위험 반영 | **핵심(§3~§6)** |
| **가맹점 리스크 현황** | 가맹점별 적용 방식·값 표 | 참고(§7) |

리스크 필터는 **본사 단위 공통 정책**입니다. 한 곳에서 켜고 끄면 정책을 따르는 전 가맹점에 즉시 적용됩니다(별도 배포·재시작 불필요, 저장 즉시 반영).

### 1.1 적용 지점

| 구분 | 시점 | 대상 PG | 동작 |
|------|------|---------|------|
| **사전 필터(Presale)** | 결제 승인 API 호출 직전 | JPAY, ChillPay | 조건 충족 시 **PG 호출 자체를 취소** |
| **사후 필터(Postsale)** | JPAY `pay_index` 응답 수신 후 | JPAY | 고위험·PY0124 판정 시 **카드 쿨다운·현황 기록** |

> 사전 필터는 이메일·전화·성명·카드번호·IP 등 **결제창에서 수집한 값**으로 판정합니다. 카드번호 기반 필터(속도제한·연락처 불일치)는 카드번호를 서버가 받는 흐름에서만 동작합니다.

## 2. 화면 진입 · 저장

1. 상단 메뉴 **본사설정 → 리스크설정** 클릭
2. 「리스크 필터링」 영역에서 각 항목을 **사용/미사용** 또는 숫자로 설정
3. 하단 **[저장]** 클릭 → 즉시 반영

> 접근 권한은 **본사설정 → 본사권한설정**에서 부여합니다. 저장 값은 `tb_hq_risk_card_policy` 단일 행(id=1)에 보관됩니다.

## 3. 사전 필터 항목별 설명

### 3.0 사전필터 사용 (마스터 스위치)

- 항목: **사전필터 사용** (`presaleFilterEnabledYn`)
- **미사용**으로 두면 아래 3.1~3.6 개별 필터가 모두 동작하지 않습니다(전체 OFF).
- 개별 필터를 조정하려면 먼저 이 값이 **사용**이어야 합니다.

### 판정 순서

사전 필터는 아래 순서로 검사하며, **먼저 걸리는 하나**에서 즉시 차단합니다.

```
① 비정상 이메일 → ② 비정상 전화번호 → ③ 의심 holder명
→ ④ 카드 속도제한 → ⑤ 이메일 속도제한 → ⑥ IP 속도제한
→ ⑦ 구매자 연락처 불일치
```

### 3.1 비정상 이메일 (`filterEmailInvalidYn`)

- 이메일 형식이 명백히 잘못된 요청을 차단합니다.
- 차단 기준
  - 기본 이메일 형식(`x@y.zz`) 위반
  - 아이디(@ 앞) 길이 2자 미만
  - 아이디가 동일 문자 반복(3자 이상, 예: `aaa@…`)
  - 도메인이 `example.*`, `test`, `test.*`
- 버튼/입력에 이메일이 없으면 검사하지 않습니다.

### 3.2 비정상 전화번호 (`filterPhoneInvalidYn`)

- 숫자만 추출해 판정합니다. 아래는 차단.
  - 자릿수 7 미만 또는 15 초과
  - 모두 같은 숫자(예: `0000000000`)
  - 연속 증가·감소 8자리 이상(예: `12345678`, `98765432`)
  - `000000`으로 시작하거나 `0000000`으로 끝남
- 전화번호가 없으면 검사하지 않습니다.

### 3.3 의심 holder명 (`filterHolderNameYn`)

- 실명이 아닌 선불·기프트·간편결제 표기의 카드 명의를 차단합니다.
- 차단 키워드(대소문자 무시, 부분일치): `GIFTCARD HOLDER`, `GIFT CARD`, `PAYPAY USER`, `VPRECA`/`V PRECA`, `MERPAY MEMBER`, `KYASH MEMBER`, `PREPAID MEMBER`, `VANDALE USER`, `BUSINESS CARD`
- 성(姓)·이름을 합친 명의로 검사합니다.

### 3.4 카드 속도 제한 (`filterVelocityCardYn`)

- **동일 카드**로 짧은 시간에 반복 시도하는 것을 차단합니다.
- 판정: 최근 **속도제한 창(분)** 안에 같은 카드(해시)·같은 가맹점 거래 수가 **속도제한 횟수 이상**이면 차단.
- 카드번호를 받는 흐름에서만 동작합니다.

### 3.5 이메일 속도 제한 (`filterVelocityEmailYn`)

- **동일 이메일**로 최근 창 안에 횟수 이상 시도하면 차단합니다(가맹점 단위 집계).

### 3.6 IP 속도 제한 (`filterVelocityIpYn`)

- **동일 접속 IP**로 최근 창 안에 횟수 이상 시도하면 차단합니다(가맹점 단위 집계).

### 3.7 구매자 연락처 불일치 (`filterBuyerContactMismatchYn`)

- **직전 동일 카드 결제 이력**과 이메일·전화·성명이 다르면 차단합니다(카드 도용 의심).
- 같은 카드(해시)의 가장 최근 거래 1건과 비교하여 이메일 → 전화 → 성명 순으로 검사하고, 하나라도 다르면 차단.
- 성명은 「성·이름 순서 뒤바뀜」은 동일로 간주합니다.
- 카드번호를 받는 흐름에서만 동작합니다.

> **연동 팁:** 「자동기억 기본값」(§4)을 **사용**으로 두면 결제창이 구매자 연락처를 기억해 재결제 시 동일 값으로 채워지므로, 정상 재구매의 오탐(불일치 차단)을 줄일 수 있습니다.

---

## 4. 속도 제한·자동기억 값

| 항목 | 필드 | 기본값 | 설명 |
|------|------|--------|------|
| 속도제한 창(분) | `velocityWindowMinutes` | 10 | 최근 N분 이내를 집계(1~1440) |
| 속도제한 횟수 | `velocityMaxAttempts` | 3 | 창 안에서 N회 이상이면 차단(1~99) |
| 자동기억 기본값 | `checkoutContactRememberDefaultYn` | 사용 | 결제창에서 이메일·전화·성명을 브라우저에 자동기억(가맹 「본사정책 따름」의 기본값) |

> 예) 창 10분 · 횟수 3 → 동일 카드로 10분 안에 3번째까지 진행되면, 그 시점 이후 시도가 차단됩니다.

## 5. JPAY 사후(Postsale) 쿨다운

JPAY는 승인 응답(`pay_index`) 이후에야 고위험 판정이 오는 경우가 있어, 사후 결과를 카드 쿨다운·현황에 반영합니다.

| 항목 | 필드 | 판정 대상 |
|------|------|-----------|
| JPAY 사후 고위험 쿨다운 | `postsaleCooldownJpayHighriskYn` | 응답 문구에 `HIGH-RISK/고위험/高リスク/高风险`, 또는 이메일·전화·성명 「불일치/MISMATCH」 계열 |
| JPAY PY0124 쿨다운 | `postsaleCooldownJpayPy0124Yn` | 응답 코드 `PY0124` 또는 "거래를 확인할 수 없음" 계열 |

- **사용**이면: 해당 실패가 **동일 카드 비성공 누적(트리거 §7)** 에 포함되고 「리스크 현황」에 기록됩니다.
- **미사용**이면: 쿨다운 집계에서 제외됩니다(현황 표시 정책은 코드 기준을 따릅니다).

## 6. 차단 시 동작 (운영자가 알아야 할 결과)

사전 필터에 걸리면 다음이 동시에 일어납니다.

1. **PG 미호출** — JPAY·ChillPay로 실제 결제 요청을 보내지 않습니다.
2. **전산 기록** — 대기 거래를 만든 뒤 **취소(상태 20)** 로 마감하며, 사유에 필터 구분이 남습니다. (결제내역상 1회 시도·취소로 보임)
3. **리스크 현황 기록** — `tb_pay_risk_filter_event`에 이벤트 1건이 적재되어 **운영관리 → 리스크 현황**에서 조회됩니다.
4. **구매자 안내** — 결제창에 사유별 안내 문구가 **결제창 언어(KO/EN/JP/CH/TH)** 로 표시됩니다.
5. **API 응답** — `success=false`, `errorCode=PRESALE_RISK_FILTER`, `filterCode=<코드>`, `txnStatus=20`.

### 필터 구분 코드 · 구매자 안내(요약)

| 코드 | 현황 표기 | 구매자 안내(KO 요약) |
|------|-----------|----------------------|
| `EMAIL_INVALID` | 비정상 이메일 | 이메일 형식이 올바르지 않습니다. |
| `PHONE_INVALID` | 비정상 전화번호 | 전화번호 형식이 올바르지 않습니다. |
| `HOLDER_NAME_SUSPICIOUS` | 의심 holder명 | 카드 명의가 정책상 허용되지 않습니다. 실명 카드로 시도하세요. |
| `VELOCITY_CARD` | 카드 속도 제한 | 동일 카드로 시도가 많습니다. 잠시 후 다시 시도하세요. |
| `VELOCITY_EMAIL` | 이메일 속도 제한 | 동일 이메일로 시도가 많습니다. 잠시 후 다시 시도하세요. |
| `VELOCITY_IP` | IP 속도 제한 | 동일 접속에서 시도가 많습니다. 잠시 후 다시 시도하세요. |
| `BUYER_EMAIL_MISMATCH` | 구매자 이메일 불일치 | 이전 결제 이메일과 다릅니다. 동일 정보로 시도하세요. |
| `BUYER_PHONE_MISMATCH` | 구매자 전화 불일치 | 이전 결제 전화와 다릅니다. 동일 정보로 시도하세요. |
| `BUYER_NAME_MISMATCH` | 구매자 성명 불일치 | 이전 결제 성명과 다릅니다. 동일 정보로 시도하세요. |
| `POSTSALE_JPAY_HIGH_RISK` | JPAY 사후 고위험 | (사후 분류 — 결제창 표시 아님) |
| `POSTSALE_JPAY_PY0124` | JPAY PY0124 | (사후 분류 — 결제창 표시 아님) |

## 7. 리스크 현황 조회 (운영관리 → 리스크 현황)

- 경로: **운영관리 → 리스크 현황**(`/risk/list`)
- 검색 조건: **업체코드**, **등록일**(기간, 미지정 시 최근 7일), **필터구분**
- 목록 컬럼: 등록일시 · 업체명 · 업체코드 · PG · 주문번호 · 거래번호 · **필터구분** · 내용
- **엑셀다운로드** 지원, 최신순 정렬.

이 화면으로 어떤 필터가 얼마나 발생하는지 확인하고, 오탐이 잦은 필터를 조정합니다.

### 트리거·비활성카드와의 관계(참고)

- 「리스크설정(트리거)」은 동일 카드 **비성공 누적**이 추적기간 안에서 N차에 도달하면 **비활성카드(마스킹)** 로 자동 등록해 이후 결제를 차단합니다.
- 사전 필터 차단(취소 20)과 JPAY 사후 고위험/PY0124(쿨다운 사용 시)은 이 누적에 반영됩니다.
- 비활성 등록·해지는 **운영관리 → 비활성카드등록**(`/ops/inactiveCard`)에서 관리하며, 카드 해지 시 해당 카드 누적도 초기화됩니다.

## 8. 운영 권장 설정 (기본 프리셋)

| 항목 | 권장 | 사유 |
|------|------|------|
| 사전필터 사용 | 사용 | 사기·도용 1차 방어 |
| 비정상 이메일/전화번호 | 사용 | 오탐이 거의 없어 항상 권장 |
| 의심 holder명 | 사용 | 선불·기프트 명의 카드 차단 |
| 카드/이메일/IP 속도제한 | 사용 | 카드 테스트(BIN attack) 방어 |
| 속도제한 창/횟수 | 10분 / 3회 | 정상 재시도는 허용, 반복 공격만 차단 |
| 구매자 연락처 불일치 | 사용 + 자동기억 사용 | 도용 방어 + 정상 재구매 오탐 최소화 |
| JPAY 사후 고위험/PY0124 쿨다운 | 사용 | 사후 고위험 카드의 즉시 재시도 억제 |

## 9. 문제 해결 (FAQ)

- **정상 고객이 계속 차단돼요.**
  - 「리스크 현황」에서 `filterCode`를 확인하세요.
  - 속도제한이면 **창(분)↓ 또는 횟수↑** 로 완화합니다.
  - 연락처 불일치가 잦으면 **자동기억 기본값=사용**으로 두어 재결제 시 동일 값이 채워지게 합니다.
- **특정 필터만 끄고 싶어요.** → 「사전필터 사용=사용」을 유지한 채 해당 항목만 **미사용**으로 저장.
- **필터를 전부 끄고 싶어요.** → 「사전필터 사용=미사용」 (사후 쿨다운은 별도 항목에서 관리).
- **차단인데 결제내역에 취소(20)만 있고 PG 로그가 없어요.** → 정상입니다. 사전 필터는 PG로 보내기 전 차단하므로 PG 승인 로그가 없습니다.
- **Eximbay 등 결제창 호스팅형 PG는요?** → 카드번호·연락처를 우리 서버가 받지 않는 흐름에서는 카드/연락처 기반 필터가 동작하지 않습니다. 사전 필터는 카드·연락처를 수집하는 JPAY·ChillPay 흐름을 대상으로 합니다.
