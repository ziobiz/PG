# 배포 및 PostgreSQL 스키마 트러블슈팅 요약

서버(VPS) 배포·`ddl-auto: validate` 실패를 줄이기 위한 정리입니다. (기록일: 2026-03-28)

## 1. 통합 마이그레이션 SQL

- 파일: `pg-app/src/main/resources/db/ALL_migrate_V2_V36_plus_check_tables_postgresql.sql`
- 용도: pgAdmin 등에서 **SECTION M**(V2~V36 DDL) 실행 후 필요 시 **SECTION C**(테이블 점검 SELECT).
- 애플리케이션이 붙는 DB와 **동일한 DB**에 실행해야 합니다.

## 2. PostgreSQL 문법: V24 `calc_cycle`

- **잘못된 예:** `ALTER COLUMN calc_cycle VARCHAR(64);`
- **올바른 예:** `ALTER COLUMN calc_cycle TYPE VARCHAR(64);`
- 원본: `pg-app/src/main/resources/db/V24_settlement_calc_cycle_extend.sql`

## 3. `tb_hq_api_config` 컬럼 누락 시

스키마 검증에서 `recall_include_fee_yn`, `chillpay_url_callback_url` 등이 없다고 하면, 앱 DB에 아래를 실행합니다 (이미 있으면 `IF NOT EXISTS` 로 무해).

```sql
ALTER TABLE tb_hq_api_config
    ADD COLUMN IF NOT EXISTS recall_include_fee_yn VARCHAR(1) DEFAULT 'N';
ALTER TABLE tb_hq_api_config
    ADD COLUMN IF NOT EXISTS settlement_vat_apply_yn VARCHAR(1) DEFAULT 'Y';
ALTER TABLE tb_hq_api_config
    ADD COLUMN IF NOT EXISTS chillpay_url_result_path VARCHAR(255);
ALTER TABLE tb_hq_api_config
    ADD COLUMN IF NOT EXISTS chillpay_url_callback_url VARCHAR(1024);
```

- 마이그레이션 원본: `V27_hq_fee_recall_vat_policy.sql`, `V35_chillpay_url_payment_hq.sql`

## 4. `tb_hq_notify_mapping.mapping_json` — TEXT vs CLOB(oid)

- DB(V21)는 `mapping_json TEXT`.
- JPA에서 **`@Lob`** 를 쓰면 Hibernate+PostgreSQL 검증이 **oid(CLOB)** 를 기대해 `TEXT` 와 충돌합니다.
- **`@JdbcTypeCode(SqlTypes.LONGVARCHAR)`** 는 JDBC 타입 `-1`(LONGVARCHAR)로, 동일하게 **CLOB(oid) 검증**으로 이어질 수 있어 **사용하지 않습니다.**
- **권장:** `PgNotifyInbound.rawBody` 와 같이 **`@Column(name = "mapping_json", columnDefinition = "TEXT")` 만** 사용합니다.
- 엔티티: `com.pg.entity.HqNotifyMappingConfig`

## 5. JAR 배포 경로

- PC에서 빌드: `pg-app` 디렉터리에서 `gradlew.bat clean bootJar` (또는 `./gradlew clean bootJar`).
- 산출물: `pg-app/build/libs/pg-app-0.0.1-SNAPSHOT.jar`
- 서버 업로드 예: `/home/ftpuser/pg-app/build/libs/pg-app-0.0.1-SNAPSHOT.jar` (기존 JAR 덮어쓰기)
- `restart-pg-app.sh` 는 위 경로의 JAR를 사용합니다. FTP 경로가 다르면 기동에 예전 JAR가 쓰일 수 있습니다.

## 6. 재시작 후 성공 확인

- 로그: `tail -n 30 /home/ftpuser/pg-app/pg-app.log`
- 정상 시 예: `Initialized JPA EntityManagerFactory`, `Tomcat started on port(s): 8080`, **`Started PgAppApplication`**
- 실패 시: `Schema-validation:` 또는 `Application run failed` 메시지를 기준으로 컬럼·타입·마이그레이션을 맞춥니다.
