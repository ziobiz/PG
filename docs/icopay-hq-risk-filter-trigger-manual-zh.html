1. 运营概览

本文档从运营角度整理：在「风险过滤」中将各开关设为启用时，实际哪些触发器在何时生效。

  • 对象: 总部运营人员 · 权限画面 M0129（风险设置）
  • 策略存储: tb_hq_risk_card_policy (id=1) · 保存后立即对全加盟商共同生效
  • 售前拦截: 调用 PG（JPAY·ChillPay·Eximbay 等）的直前
  • 售后冷却: JPAY pay_index 之后的高风险·PY0124（独立开关）

2. 风险设置 vs 风险过滤

区域触发结果
风险设置（风险管理）同一卡非成功（FAIL·取消·无效·未支付等）累计1～4 次等待 · 非活动卡自动登记
风险过滤格式·速度·联系方式不一致·可疑名义等不调用 PG · 系统取消(20) · 风险现状
加盟商风险现状按加盟商的风险管理方式（总部/单独/未使用）显示触发等待时间·自动登记的适用值

加盟商「单独设置/未使用」优先于风险管理（累计触发）。售前过滤开关遵循总部策略。

3. 整体处理流程

买家尝试支付 → （卡品牌·策略等其他检查） → 【售前过滤启用=Y】则按项检查（§5 顺序） → 违规时: 不调用 PG · 取消(20) · 风险现状 · 买家提示 → 通过时: 向 PG 发起批准请求 → （仅 JPAY）售后高风险/PY0124 → 冷却·现状（对应开关=Y 时）
托管（不采集卡号）流程: 以邮箱·电话·姓名·IP·邮箱速度为主。无卡哈希时，卡速度与联系方式不一致实质上跳过。

4. 按项「启用」时的行为

将画面各项保存为启用(Y)后，下列触发器生效。未使用(N)则仅跳过该项检查。

4.0 售前过滤启用（主开关）

区分内容
字段presaleFilterEnabledYn
启用评估 §4.1～4.8 各售前过滤项
未使用即使单项为 Y 也全部跳过。不影响 JPAY 售后冷却（§4.9～4.10）

4.1 异常邮箱

区分内容
代码EMAIL_INVALID
启用时邮箱非空但格式错误、本地部分不足 2 字或同一字符重复、域名为 test./example. 时拦截
备注值为空时不执行本检查

4.2 异常电话

区分内容
代码PHONE_INVALID
启用时仅提取数字后长度不在 7～15、同一数字重复、连续增减、000000 模式等则拦截
备注为空则跳过

4.3 可疑 holder 名

区分内容
代码HOLDER_NAME_SUSPICIOUS
启用时名义含 Giftcard Holder、PayPay User、Merpay/Kyash Member、Business Card、VPRECA 等预付·代行·可疑文案则拦截

4.4 买家联系方式不一致

区分内容
代码BUYER_EMAIL_MISMATCH / BUYER_PHONE_MISMATCH / BUYER_NAME_MISMATCH
启用时与同一卡（哈希）·同一加盟商的最近 1 笔比较。邮箱·电话·姓名不同则拦截
备注仅姓与名顺序对调不视为不一致。无卡哈希则跳过

4.5～4.7 速度限制（卡 · 邮箱 · IP）

项目代码启用时
卡速度限制VELOCITY_CARD同一卡·加盟商在窗口（分钟）内尝试次数 ≥ 次数 → 拦截
邮箱速度限制VELOCITY_EMAIL同一邮箱·加盟商适用相同条件
IP 速度限制VELOCITY_IP同一买家 IP·加盟商适用相同条件
共用参数字段默认 · 范围
速度限制窗口（分钟）velocityWindowMinutes10 · 1～1440
速度限制次数velocityMaxAttempts3 · 1～99

4.9 JPAY 售后高风险冷却

区分内容
代码POSTSALE_JPAY_HIGH_RISK
启用时在 JPAY 批准请求之后，将高风险失败反映到卡冷却·风险现状
未使用该分类不纳入冷却汇总

4.10 JPAY PY0124 冷却

区分内容
代码POSTSALE_JPAY_PY0124
启用时对 JPAY PY0124 失败按与高风险相同方式记录冷却·现状

5. 售前过滤检查顺序

售前过滤启用=Y 时，代码按下列顺序评估，并在首次违规处立即中止。

  1. 异常邮箱 — EMAIL_INVALID
  2. 异常电话 — PHONE_INVALID
  3. 可疑 holder 名 — HOLDER_NAME_SUSPICIOUS
  4. 卡速度限制 — VELOCITY_CARD
  5. 邮箱速度限制 — VELOCITY_EMAIL
  6. IP 速度限制 — VELOCITY_IP
  7. 买家联系方式不一致 — BUYER_*_MISMATCH（邮箱 → 电话 → 姓名）
① EMAIL_INVALID → ② PHONE_INVALID → ③ HOLDER_NAME_SUSPICIOUS → ④ VELOCITY_CARD → ⑤ VELOCITY_EMAIL → ⑥ VELOCITY_IP → ⑦ BUYER_EMAIL / PHONE / NAME_MISMATCH
若单项开关为未使用，则仅跳过该步骤。例: 仅关闭邮箱格式 → 跳过 ①，从 ② 继续。

6. 拦截结果 · 运营确认

  1. 不向 PG 发送批准请求
  2. 系统记录 1 次尝试·状态取消(20)
  3. 写入 tb_pay_risk_filter_event → 运营管理 → 风险现状
  4. 买家响应: 多语言消息 · 错误码 PRESALE_RISK_FILTER

若正常客户被拦截，请查看现状中的 filterCode，仅放宽该项（未使用）或调整速度窗口/次数。

7. 运营建议 · FAQ

项目建议
售前过滤启用启用
格式·holder·速度 3 种启用 · 窗口 10 分 / 次数 3 次
联系方式不一致启用（自动记忆在支付·URL 选项卡）
JPAY 售后 2 种启用
  • 仅关闭部分: 保持售前过滤=启用，仅将问题项设为未使用
  • 全部关闭: 售前过滤=未使用（单项为 Y 也不运行）
  • PG 日志无交易: 多为售前拦截正常工作
  • 自动记忆: 不在「风险过滤」下；总部政策 → 支付·URL → 支付窗显示默认值
