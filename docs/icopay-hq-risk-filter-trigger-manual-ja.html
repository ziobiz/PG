1. 運用概要

本ドキュメントは、「リスクフィルタリング」で各スイッチを使用にした場合に実際にどのトリガーがいつ動作するかを運用視点で整理します。

  • 対象: 本社運用者 · 権限画面 M0129（リスク設定）
  • ポリシー保存: tb_hq_risk_card_policy (id=1) · 保存直後に全加盟店共通適用
  • 事前遮断: PG（JPAY·ChillPay·Eximbay 等）呼出の直前
  • 事後クールダウン: JPAY pay_index 以降の高リスク·PY0124（独立スイッチ）

2. リスク設定 vs リスクフィルタリング

領域トリガー結果
リスク設定（危険管理）同一カード非成功（FAIL·取消·無効·未決済など）累積1〜4次待機 · 非活性カード自動登録
リスクフィルタリング形式·速度·連絡先不一致·疑わしい名義などPG未呼出 · 電算取消(20) · リスク現状
加盟店リスク現状加盟店別危険管理方式（本社/別途/未使用）トリガー待機時間·自動登録の適用値を表示

加盟店の「別途設定/未使用」は危険管理（累積トリガー）に優先します。事前フィルタスイッチは本社ポリシーに従います。

3. 全体処理フロー

購入者の決済試行 → （カードブランド·ポリシーなどその他検査） → 【事前フィルタ使用=Y】なら項目別検査（§5の順） → 違反時: PG未呼出 · 取消(20) · リスク現状 · 購入者案内 → 通過時: PG承認リクエスト → （JPAYのみ）事後高リスク/PY0124 → クールダウン·現状（該当スイッチ=Yのとき）
ホステッド（カード番号未収集）フロー: メール·電話·氏名·IP·メール速度が中心。カードハッシュがなければカード速度·連絡先不一致は実質スキップ。

4. 項目別「使用」時の動作

画面の各項目を使用(Y)で保存すると、下記トリガーが有効になります。未使用(N)なら該当検査のみスキップします。

4.0 事前フィルタ使用（マスター）

区分内容
フィールドpresaleFilterEnabledYn
使用§4.1〜4.8の個別事前フィルタを評価
未使用個別がYでもすべてスキップ。JPAY事後クールダウン（§4.9〜4.10）には影響なし

4.1 異常メール

区分内容
コードEMAIL_INVALID
使用時メールが空でなく形式が不正、ローカル部2文字未満·同一文字繰返し、test./example.ドメインなら遮断
備考値が空ならこの検査は行わない

4.2 異常電話番号

区分内容
コードPHONE_INVALID
使用時数字のみ抽出後の長さが7〜15外、同一数字繰返し、連続増減、000000パターンなどなら遮断
備考空ならスキップ

4.3 疑わしいholder名

区分内容
コードHOLDER_NAME_SUSPICIOUS
使用時名義に Giftcard Holder、PayPay User、Merpay/Kyash Member、Business Card、VPRECA などプリペイド·代行·疑わしい文言があれば遮断

4.4 購入者連絡先不一致

区分内容
コードBUYER_EMAIL_MISMATCH / BUYER_PHONE_MISMATCH / BUYER_NAME_MISMATCH

備考姓·名の順序入替のみでは不一致としない。カードハッシュがなければスキップ

5. 事前フィルタ検査順

事前フィルタ使用=Yのとき、コードは下記の順で評価し、最初の違反で直ちに中断します。

  1. 異常メール — EMAIL_INVALID
  2. 異常電話番号 — PHONE_INVALID
  3. 疑わしいholder名 — HOLDER_NAME_SUSPICIOUS
  4. カード速度制限 — VELOCITY_CARD
  5. メール速度制限 — VELOCITY_EMAIL
  6. IP速度制限 — VELOCITY_IP
  7. 購入者連絡先不一致 — BUYER_*_MISMATCH（メール → 電話 → 氏名）
① EMAIL_INVALID → ② PHONE_INVALID → ③ HOLDER_NAME_SUSPICIOUS → ④ VELOCITY_CARD → ⑤ VELOCITY_EMAIL → ⑥ VELOCITY_IP → ⑦ BUYER_EMAIL / PHONE / NAME_MISMATCH
個別スイッチが未使用なら該当ステップのみスキップします。例: メール形式だけOFF → ①をスキップし②から。

6. 遮断結果 · 運用確認

  1. PGへ承認リクエストを送らない
  2. 電算に1回試行·状態取消(20)を記録
  3. tb_pay_risk_filter_eventへ格納 → 運用管理 → リスク現状
  4. 購入者応答: 多言語メッセージ · エラーコード PRESALE_RISK_FILTER

正常顧客が遮断された場合は現状のfilterCodeを確認し、該当項目のみ緩和（未使用）するか、速度窓/回数を調整します。

7. 運用推奨 · FAQ

項目推奨
事前フィルタ使用使用
形式·holder·速度3種使用 · 窓10分 / 回数3回
連絡先不一致使用（自動記憶は決済·URLタブ）
JPAY事後2種使用
  • 一部のみOFF: 事前フィルタ=使用を維持し、問題項目のみ未使用
  • すべてOFF: 事前フィルタ=未使用（個別Yでも動作しない）
  • PGログに取引なし: 事前遮断が正常動作したケース
  • 自動記憶: 「リスクフィルタリング」ではなく、本社ポリシー → 決済·URL → 決済画面表示の既定値

フィールド·DB·コード表はフィルタ詳細マニュアルを参照してください。
