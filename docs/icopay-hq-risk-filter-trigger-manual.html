1. 운영 개요

본 문서는 「리스크 필터링」에서 각 스위치를 사용으로 두었을 때 실제로 어떤 트리거가 언제 동작하는지를 운영 관점에서 정리합니다.

  • 대상: 본사 운영자 · 권한 화면 M0129(리스크설정)
  • 정책 저장: tb_hq_risk_card_policy (id=1) · 저장 즉시 전 가맹 공통 적용
  • 사전 차단: PG(JPAY·ChillPay·Eximbay 등) 호출 직전
  • 사후 쿨다운: JPAY pay_index 이후 고위험·PY0124 (독립 스위치)

2. 리스크설정 vs 리스크 필터링

영역트리거결과
리스크설정 (위험관리)동일 카드 비성공(FAIL·취소·무효·미결제 등) 누적1~4차 대기 · 비활성카드 자동등록
리스크 필터링형식·속도·연락처 불일치·의심 명의 등PG 미호출 · 전산 취소(20) · 리스크 현황
가맹점 리스크 현황가맹별 위험관리 방식(본사/별도/미사용)트리거 대기 시간·자동등록 적용 값 표시

가맹 「별도설정/미사용」은 위험관리(누적 트리거)에 우선합니다. 사전 필터 스위치는 본사 정책을 따릅니다.

3. 전체 처리 흐름

구매자 결제 시도 → (카드 브랜드·정책 등 기타 검사) → 【사전필터 사용=Y】이면 항목별 검사 (§5 순서) → 위반 시: PG 미호출 · 취소(20) · 리스크 현황 · 구매자 안내 → 통과 시: PG 승인 요청 → (JPAY만) 사후 고위험/PY0124 → 쿨다운·현황 (해당 스위치=Y일 때)
호스티드(카드번호 미수집) 흐름: 이메일·전화·성명·IP·이메일 속도가 중심. 카드 해시가 없으면 카드 속도·연락처 불일치는 사실상 skip.

4. 항목별 「사용」 시 동작

화면의 각 항목을 사용(Y)으로 저장하면 아래 트리거가 활성화됩니다. 미사용(N)이면 해당 검사만 건너뜁니다.

5. 사전필터 검사 순서

사전필터 사용=Y일 때, 코드는 아래 순서로 평가하며 첫 위반에서 즉시 중단합니다.

  1. 비정상 이메일 — EMAIL_INVALID
  2. 비정상 전화번호 — PHONE_INVALID
  3. 의심 holder명 — HOLDER_NAME_SUSPICIOUS
  4. 카드 속도 제한 — VELOCITY_CARD
  5. 이메일 속도 제한 — VELOCITY_EMAIL
  6. IP 속도 제한 — VELOCITY_IP
  7. 구매자 연락처 불일치 — BUYER_*_MISMATCH (이메일 → 전화 → 성명)
① EMAIL_INVALID → ② PHONE_INVALID → ③ HOLDER_NAME_SUSPICIOUS → ④ VELOCITY_CARD → ⑤ VELOCITY_EMAIL → ⑥ VELOCITY_IP → ⑦ BUYER_EMAIL / PHONE / NAME_MISMATCH
개별 스위치가 미사용이면 해당 단계만 건너뜁니다. 예: 이메일 형식만 OFF → ① 스킵 후 ②부터.

6. 차단 결과 · 운영 확인

  1. PG로 승인 요청을 보내지 않음
  2. 전산에 1회 시도·상태 취소(20) 기록
  3. tb_pay_risk_filter_event 적재 → 운영관리 → 리스크 현황
  4. 구매자 응답: 다국어 메시지 · 오류코드 PRESALE_RISK_FILTER

정상 고객이 막히면 현황의 filterCode를 확인한 뒤 해당 항목만 완화(미사용)하거나 속도 창/횟수를 조정합니다.
