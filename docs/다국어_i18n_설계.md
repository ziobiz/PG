# PG 통합관리자 - 다국어(i18n) 설계

> **작성일**: 2025-02-27  
> **지원 언어**: 한국어(ko), 일본어(ja), 영어(en), 태국어(th), 중국어(zh)

---

## 1. 개요

### 1.1 지원 언어

| 코드 | 언어 | 비고 |
|------|------|------|
| `ko` | 한국어 | 기본(기준) |
| `ja` | 日本語 | |
| `en` | English | |
| `th` | ไทย | |
| `zh` | 中文 | 간체 기준 |

### 1.2 적용 범위

| 구분 | 대상 | 방식 |
|------|------|------|
| **프론트엔드** | 메뉴, 폼 라벨, 버튼, 알림, 빈 메시지, 모달 | JSON 로케일 파일 + `t(key)` |
| **백엔드** | API 응답 메시지, 검증 오류 | Spring MessageSource |
| **HTML** | index.html, login.html, pay.html | data-i18n 속성 또는 JS 주입 |

## 2. 아키텍처

### 2.1 전체 흐름

```
[사용자] → 언어 선택(쿠키/세션) → [프론트] t('key') → locale/ko.json
                                    [백엔드] Accept-Language → MessageSource
```

### 2.2 키 체계

```
{도메인}.{화면/컨텍스트}.{요소}
```

**예시**

| 키 | ko | en |
|----|----|-----|
| `common.save` | 저장 | Save |
| `common.search` | 검색 | Search |
| `common.cancel` | 취소 | Cancel |
| `menu.hq` | 본사설정 | HQ Settings |
| `menu.comp` | 업체관리 | Company |
| `comp.reg.title` | 업체등록 | Company Registration |
| `comp.detail.parentComp` | 상위 본사 | Parent Company |
| `comp.div.REGIONAL` | 본사 | Regional HQ |
| `error.notFound` | 찾을 수 없습니다. | Not found. |
| `api.comp.notFound` | 업체를 찾을 수 없습니다. | Company not found. |

### 3.3 i18n.js API

```javascript
// 초기화 (페이지 로드 시)
PG_I18n.init({ defaultLocale: 'ko', storageKey: 'pg_locale' });

// 번역
t('common.save');           // "저장"
t('comp.div.REGIONAL');     // "본사"
t('comp.msg.saveSuccess', { name: '업체' });  // 플레이스홀더 지원 시

// 언어 변경
PG_I18n.setLocale('ja');
// 화면 전체 리렌더 또는 t() 재호출
```

### 3.4 screens.js 변환 방식

**변경 전**

```javascript
{ label: '업체코드', type: 'text', name: 'searchCompId' }
```

**변경 후**

```javascript
{ labelKey: 'comp.label.compId', type: 'text', name: 'searchCompId' }
// 또는 런타임에: { label: t('comp.label.compId'), ... }
```

- **권장**: `labelKey` 사용 → 렌더 시 `t(labelKey)` 호출
- `options`의 `t` → `tKey`로 변경: `{ v: 'Y', tKey: 'common.yes' }`

### 3.5 HTML (index.html) 처리

```html
<!-- data-i18n로 키 지정 -->
<span data-i18n="menu.hq">본사설정</span>
<button data-i18n="common.search">검색</button>

<!-- JS 초기화 시 -->
document.querySelectorAll('[data-i18n]').forEach(el => {
  el.textContent = t(el.getAttribute('data-i18n'));
});
```

### 3.6 언어 선택 UI

- 헤더 또는 푸터에 언어 드롭다운
- 선택 시 `setLocale()` → 쿠키/로컬스토리지 저장 → 화면 갱신

## 4. 백엔드 설계

### 4.1 Spring MessageSource

```
pg-app/src/main/resources/
├── messages/
│   ├── messages.properties      # 기본(ko)
│   ├── messages_ko.properties
│   ├── messages_ja.properties
│   ├── messages_en.properties
│   ├── messages_th.properties
│   └── messages_zh.properties
```

### 4.2 messages.properties 예시

```properties
# API 공통
api.success=저장되었습니다.
api.error.notFound=찾을 수 없습니다.

# 업체
api.comp.notFound=업체를 찾을 수 없습니다.
api.comp.noPermission=본사는 직접 수정할 수 없습니다. 총본사만 수정 가능합니다.
api.comp.validation.parentInvalid=업체구분에 맞는 상위 조직이 아닙니다.

# 인증
api.auth.required=아이디와 비밀번호를 입력하세요.
api.auth.fail=아이디 또는 비밀번호가 올바르지 않습니다.
```

### 4.3 Locale 결정

1. **API 요청**: `Accept-Language` 헤더 (예: `Accept-Language: ja`)
2. **쿼리 파라미터**: `?lang=ja` (선택)
3. **기본값**: `ko`

### 4.4 Controller 사용 예

```java
@RestController
public class ApiCompController {
    private final MessageSource messageSource;

    public ResponseEntity<ApiResponse<?>> update(..., @RequestHeader(value = "Accept-Language", required = false) String acceptLang) {
        Locale locale = parseLocale(acceptLang);
        // ...
        return ResponseEntity.ok(ApiResponse.fail(
            messageSource.getMessage("api.comp.notFound", null, locale),
            "NOT_FOUND"
        ));
    }
}
```

### 4.5 LocaleResolver (선택)

```java
@Bean
public LocaleResolver localeResolver() {
    AcceptHeaderLocaleResolver r = new AcceptHeaderLocaleResolver();
    r.setDefaultLocale(Locale.KOREAN);
    return r;
}
```

## 5. 구현 단계

### Phase 1: 기반 구축

1. `site/js/i18n.js` 작성 (t, setLocale, getLocale)
2. `site/js/locale/ko.json` 작성 (기존 한국어 문자열 추출)
3. `index.html`에 i18n.js 로드, 언어 선택 UI 추가
4. `screens.js`에 `labelKey` 지원 추가 (기존 `label`과 병행)

### Phase 2: 프론트 적용

1. `screens.js` 전체를 `labelKey`/`tKey`로 전환
2. `app.js`의 `alert()`, `innerHTML` 문자열을 `t()` 호출로 전환
3. `index.html`, `login.html`, `pay.html`에 `data-i18n` 적용

### Phase 3: 백엔드 적용

1. `messages_*.properties` 파일 생성
2. `MessageSource` Bean 설정
3. Controller의 하드코딩 메시지를 `messageSource.getMessage()`로 전환

### Phase 4: 번역

1. ko.json을 기준으로 ja, en, th, zh 번역
2. messages_ja.properties 등 번역

## 6. 주의사항

### 6.1 동적 텍스트

- **날짜/숫자 포맷**: `Intl.DateTimeFormat`, `Intl.NumberFormat` 사용
- **복수형**: 언어별 규칙 상이 → 키 분리 (`item.one`, `item.many`) 또는 ICU MessageFormat

### 6.2 RTL

- 아랍어 등 RTL 미지원 시 제외. 현재 5개 언어는 LTR.

### 6.3 API 에러코드

- `errorCode`는 언어 무관하게 유지 (예: `NOT_FOUND`, `VALIDATION`)
- `message`만 번역

### 6.4 기존 코드 호환

- `label`과 `labelKey` 병행 시: `labelKey` 우선, 없으면 `label` 사용
- 점진적 전환 가능

## 7. 키 목록 (초안)

도메인별로 키를 체계화할 때 참고용입니다.

| 도메인 | 키 접두사 | 예시 |
|--------|-----------|------|
| 공통 | `common.` | save, search, cancel, excel |
| 메뉴 | `menu.` | hq, comp, compReg, commission |
| 업체 | `comp.` | div.*, label.*, msg.* |
| 수수료 | `commission.` | title, perTxFee, payRate |
| 결제 | `payment.` | amount, status |
| 정산 | `settlement.` | cycle, transfer |
| API 에러 | `api.{domain}.` | notFound, noPermission |
| 인증 | `auth.` | login, logout, required |
