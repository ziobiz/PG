# 노티매핑설정 (본사설정)

## 목적

1. **컬럼 카탈로그** — 통합 결제내역 **VIEW SETTING**과 동일한 열 집합이 기본입니다. 단일 기준: 프론트 `site/js/pay-list-integrated-catalog.js`, 서버 `pg-app/src/main/resources/catalog/pay-list-integrated-default.json`(노티 초기·보강·`[기본 카탈로그·화면연결 삽입]`). 두 파일의 열·헤더그룹을 함께 유지합니다.
2. **결제관리 화면별 적용** — 결제내역·성공내역·URL결제내역 등 각 메뉴 URL이 어떤 카탈로그를 쓸지 연결합니다. 연결된 카탈로그의 **표시 제목**이 해당 탭·헤더 제목으로 노출됩니다.
3. **PG별 노티 매핑** — CALLBACK(서버 노티)·RESULT(브라우저)·RETURN(동기 return 등) 채널별로 PG 파라미터명(`pgField`)을 내부 열 키(`internalKey`)에 연결합니다.

- 메뉴: **본사설정 → 노티매핑설정**
- 저장: DB `tb_hq_notify_mapping.mapping_json` (단일 행)
- API: `GET/POST /api/hq/notifyMapping` · `POST /api/hq/notifyMapping/save` · `GET /api/hq/notifyMapping/defaults`
- 결제 화면 레이아웃(인증 사용자): `GET /api/calc/payListScreenLayout?pageUrl=...`

## JSON 스키마 (v2)

| 필드 | 설명 |
|------|------|
| `version` | `2` 권장 |
| `memo` | 운영 메모 |
| `columnCatalogs` | 카탈로그 배열 |
| `pageCatalogAssignments` | 화면 URL → 카탈로그 ID |
| `vendors` | PG별 채널·필드 매핑 |

### `columnCatalogs[]`

| 필드 | 설명 |
|------|------|
| `catalogId` | 고유 ID (예: `cat_pay_integrated_default`) |
| `displayTitle` | 결제관리 탭·상단 제목으로 사용 |
| `headerGroups` | 2단 헤더 그룹 `[{ "label", "keys": [] }]` |
| `columns` | `[{ "key", "label", "visible", "order" }]` — `key`는 결제내역 그리드 키와 동일해야 함 |

### `pageCatalogAssignments[]`

| 필드 | 설명 |
|------|------|
| `pageUrl` | 예: `/calc/paySuccessList` |
| `catalogId` | 위 카탈로그 ID |

### `vendors[]` · `channels[]` · `fieldMappings[]`

(v1과 동일 개념, RETURN 채널 추가 가능)

| 필드 | 설명 |
|------|------|
| `vendorCode` | `pg_cd` 와 맞출 것 (API연동설정) |
| `channelCode` | `CALLBACK` / `RESULT` / `RETURN` 등 |
| `targetPageUrl` | 전산 경로(참고·연동용) |
| `fieldMappings` | `pgField`, `internalKey`, `note` |

## 기존 v1 데이터

DB에 `version: 1` 만 있는 경우에도 `payListScreenLayout` 조회 시 서버가 기본 `columnCatalogs`·`pageCatalogAssignments`를 메모리에서 보강해 레이아웃을 계산합니다. 편집기에서 **[기본 카탈로그·화면연결 삽입]** 으로 v2 구조를 저장할 수 있습니다.

## 연동

- 결제내역 계열 화면은 로그인 후 `payListScreenLayout` 결과로 열 순서·라벨·2단 헤더·탭 제목을 덮어씁니다.
- PG 노티 수신 시 본 JSON을 읽어 `PgTrnsctn` 적재·검증에 반영하는 것은 별도 단계에서 연결하면 됩니다.
