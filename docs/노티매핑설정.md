# 노티매핑설정 (본사설정)

## 목적

PG사(칠페이, 제이페이 등)가 **CALLBACK**(서버 노티), **RESULT**(브라우저 리다이렉트) 등으로 넘기는 파라미터를, 전산의 **어느 화면**에 쌓고 **어떤 그리드/필드 키**로 보여줄지 정의합니다.  
결제대행사가 늘어나면 JSON의 `vendors` 배열에 같은 구조로 항목을 추가합니다.

- 메뉴: **본사설정 → 노티매핑설정**
- API: `GET/POST /api/hq/notifyMapping` · `POST /api/hq/notifyMapping/save`
- 저장: DB `tb_hq_notify_mapping.mapping_json` (단일 행)

## JSON 스키마 (개요)

| 필드 | 설명 |
|------|------|
| `version` | 스키마 버전 (숫자) |
| `memo` | 운영 메모 |
| `vendors` | PG사별 배열 |

### `vendors[]`

| 필드 | 설명 |
|------|------|
| `vendorCode` | PG 코드 (예: `CHILLPAY`, `JPAY`) |
| `vendorName` | 표시명 |
| `channels` | 노티 채널별 배열 |

### `channels[]`

| 필드 | 설명 |
|------|------|
| `channelCode` | `CALLBACK`, `RESULT`, (추가 시 `BACKGROUND` 등) |
| `channelName` | 설명 |
| `targetPageUrl` | 전산 내 경로 (예: `/calc/payList`) |
| `targetPageLabel` | 화면 이름 |
| `fieldMappings` | PG 필드 → 전산 필드 |

### `fieldMappings[]`

| 필드 | 설명 |
|------|------|
| `pgField` | 피지사 파라미터/필드명 |
| `internalKey` | 결제내역 그리드 등 내부 키 (`chillTransactionId`, `orderNo` …) |
| `note` | 비고 |

## 연동 단계

현재는 **설정 저장·조회**까지 제공합니다. 실제 노티 수신 시 본 JSON을 읽어 `PgTrnsctn` 적재·화면 분기에 반영하는 것은 이후 작업으로 붙이면 됩니다.

## 로컬 확인

- 화면: http://localhost:8080 → 본사설정 → 노티매핑설정  
- 저장 후 JSON이 유효한지 브라우저에서 `JSON.parse`로 검증됩니다.
