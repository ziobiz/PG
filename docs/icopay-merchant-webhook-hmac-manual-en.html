1. Scope

Background server webhook after payment confirm, and how to verify HMAC when signing is Active. Separate from browser Result URL. Payload stays ICOPAY-neutral (no PG name).

2. Notify paths

PathSenderNotes
PrimaryNOTI → merchant callbackUrlServer POST on confirm
SecondaryICOPAY → Background / inbound notify URLsSame header/secret when signing ON
ICOPAY syncs signing settings to NOTI. Verify once for both paths.

3. STEP 1 Admin settings

Menu: HQ Policy > Payment routing > Webhook signing
Menu: Company > Merchant detail > Webhook signing

HQ default is usually OFF. Merchant can set Follow HQ / Active / Inactive (merchant wins). After Active, Rotate secret (plaintext once) → store only on merchant server.

4. STEP 2 Signature spec

ItemDetail
HeaderX-Icopay-Signature: v1={hex}
AlgoHMAC-SHA256
Messageraw HTTP body (no re-serialize)
Fail / OKHTTP 401 / 200
expected = HMAC_SHA256_HEX(raw_body, webhook_secret)
header   = "v1=" + expected

5. STEP 3 Merchant server

  • HTTPS
  • Idempotent handling
  • Verify HMAC before JSON parse when signing ON
  • Env e.g. ICOPAY_WEBHOOK_SIGN_SECRET

9. FAQ

Merchant Active while HQ OFF?
Yes — merchant override signs.
Lost the secret?
Rotate again and update the server; plaintext is shown only once.
Signature mismatch?
Use raw body bytes; do not re-stringify JSON. Check v1= format and secret.
