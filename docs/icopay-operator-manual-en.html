1. Merchant Registration

Merchant Mgmt > Register Merchant / Merchant Info

1-1. New Merchant Registration Process

①Go to Merchant Mgmt > Register Merchant
②Enter basic info — business name, registration number, representative, contact, email, address
③Configure settlement structure — cycle, fee rate, bank account
④Activate desired payment services (see each service section below)
⑤Save → Merchant code (slug) auto-generated → Review payment URL
⑥Create merchant account (ID + temporary password) and deliver to merchant contact

1-2. Activatable Payment Services at Registration

ServiceActivation FieldNotes
Web Payment (URL Payment)Web payment enabled Y/NChillPay integration based
Subscription PaymentSubscription enabled Y/NSubscription plan setup required
Re-purchase PaymentRe-purchase enabled Y/NReuses existing payment token

Chatbot PaymentChatbot payment enabled Y/NAdditional setup required in Chatbot Mgmt
Setting a service to Y makes its payment URL visible in the merchant portal. With N, the URL is hidden and unavailable to the merchant.

  • Toggle account active/inactive status

5. Re-purchase Payment Setup

Merchant Mgmt > Merchant Info > Payment Settings tab

5-1. What is Re-purchase Payment?

Re-purchase payment allows customers to reuse their saved payment token from a previous transaction to make a new payment instantly without re-entering card details.

Only customers with a saved card token (from a prior transaction) can use re-purchase payment.
Difference vs. Subscription: Subscription auto-charges on a schedule; re-purchase is customer-initiated.

5-2. Enable Re-purchase Payment

①Merchant Info → Payment Settings → Set Re-purchase enabled to Y and save
②The merchant's checkout page will display a "Pay with saved card" option
③Customer selects re-purchase → payment processed immediately using saved token

5-3. Key Re-purchase Settings

FieldDescription
Re-purchase enabledActivate re-purchase payment (Y/N)
Token validity periodDuration (days) to retain the card token
Re-purchase historyView and refund re-purchase transactions
Security: Card tokens are encrypted per PCI-DSS. Actual card numbers are never stored. Deleting a token disables re-purchase for that customer.

Frequently Asked Questions (FAQ)

An HQ Admin says the Notification Management menu is missing.
Notification Management is a Super Admin exclusive menu. HQ Admin and Distributor share the same permissions and cannot access it. Request Notify URL changes from the Super Admin.
The Split Pay Email Settings option appears greyed out.
Email Settings under Split Pay Management is Super Admin only. Request template changes from the Super Admin.
A merchant says the payment URL is not visible after activation.
Verify the service's enabled field is set to Y in Merchant Info. With N, the URL is hidden in the merchant portal.
Cannot add more chatbot products for a merchant.
The merchant has reached its product slot limit. Increase the slot count in Merchant Info > Chatbot Settings.
Run Settlement / Distribute Settlement menus are not visible to HQ Admins.
These are Super Admin exclusive menus. Request settlement execution from the Super Admin if needed.
Where can I find the API documentation?
Go to Deploy Settings > API Documentation. This menu is accessible to all roles (Super Admin, HQ Admin, Distributor).
