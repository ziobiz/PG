15. FAQ — Frequently Asked Questions

Why did the menu structure change in V2.0?
ICOPAY V2.0 consolidates related settings into function-hub screens. Fees & Risk, Payments & URL, Notify Center, and similar areas are managed via tabs on one hub screen. Legacy menu URLs and permission keys are unchanged; sidebar labels use HQ Policy (본사정책) with Platform placed after AI & Chatbot.
Can we revert to Layout A (old menu names)?
ICOPAY V2.0 is the current menu layout; reverting to LEGACY is optional via ?menu=legacy. All functionality remains the same — features are accessible as tabs within V2.0 hubs. For example, the old "Fee Settings" menu is now at HQ Policy > Fees & Risk Hub > Fees Tab. Version history: HQ Policy > Platform > Release notes.
I'm an HQ account but cannot see the "HQ Policy" menu.
"HQ Policy" and "Integration & Deploy" are Super Admin exclusive menus. HQ and Distributor roles do not have access. Contact the Super Admin for any configuration changes needed.
The Run Settlement and Deploy Settlement menus are not visible.
Settlement Run, Deploy, Pending, and Unified Settlement are Super Admin-only menus. HQ and Distributor roles can only view settlement results (Merchant Settlement, Fee History, Balance History, etc.).
Can PG provider MIDs or API keys be exposed to merchants?
No. PG MIDs and API keys are used only on ICOPAY's internal servers. They are never included in merchant API responses or notify payloads. Only ICOPAY aggregate MIDs (order_id based) are passed to merchants.
Notify config changes — do they apply to pending retries immediately?
Changes take effect immediately after saving. However, notifications already in the retry queue will be processed under the old policy. Only new failures after the change will use the new retry policy.
When should we re-issue a merchant's API Key?
Re-issue in cases of suspected security incident, key leakage, or merchant request. Go to Integration & Deploy > Merchant API Launch > ③ Keys & Docs tab. The old key is immediately invalidated upon re-issuance — update the new key in the merchant's server right away.
Does blacklisting a card in the Risk tab block it across all merchants?
Yes. Cards, IPs, or emails registered in the system-wide blacklist are blocked for all merchants using ICOPAY. For merchant-specific blocks only, register separately in that merchant's individual risk settings.
