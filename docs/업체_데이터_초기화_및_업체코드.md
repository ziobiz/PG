# 업체 데이터 초기화 · 업체코드 규칙

## 업체코드 (자동 부여 · 변경 불가)

- **총본사~가맹점** 등록 시 화면에서 업체코드를 입력하지 않습니다.
- 저장 시 서버가 **업체구분별 접두(2자리) + 일련번호(8자리)** 로 자동 생성합니다.  
  (예: 본사 `11xxxxxxxx`, 가맹점 `20xxxxxxxx` — `CompService.generateNextCompCode`)
- **수정(update) API·화면에서는 업체코드(`code`)를 바꾸지 않습니다.** (조회 키로만 사용)

## 기존 업체 전부 삭제 → OTL HQ(HQ01)만

### 방법 1: dev API (로컬 권장)

1. 서버를 **dev** 프로파일로 실행 (`--spring.profiles.active=dev`)
2. 브라우저 또는 curl로 호출:  
   `GET http://localhost:8080/api/dev/reset-org-hierarchy`
3. **ADMIN**을 제외한 사용자·로그인 토큰이 삭제되므로 **admin으로 다시 로그인**합니다.

### 방법 2: 기동 시 자동 초기화

`application-dev.yml` 또는 실행 인자에서:

```yaml
app:
  data:
    reset-org-hierarchy-on-startup: true
```

**주의:** `true`이면 **애플리케이션을 재시작할 때마다** 업체가 다시 비워집니다.  
1회만 비우고 등록을 이어가려면 `false`로 두고 **방법 1**을 사용하세요.

### 운영(PostgreSQL) DB

- 기본 `application.yml`에서는 `reset-org-hierarchy-on-startup: false` 입니다.
- 필요 시 **일시적으로만** `true` 또는 dev에서 초기화 후 DB 덤프 반영 등으로 운영 정책에 맞게 처리하세요.
- `/api/dev/*`는 **dev 프로파일에서만** 동작하도록 되어 있습니다.

## 초기 시드 동작 (변경 사항)

- DB가 비어 있을 때 DataLoader는 **OTL HQ(HQ01) + 최소 프로필·정산·수수료부가**만 만듭니다.
- 예전 데모 트리(A01, M100 등)는 `app.data.seed-legacy-demo-hierarchy=true` 일 때만 생성됩니다 (기본 `false`).
