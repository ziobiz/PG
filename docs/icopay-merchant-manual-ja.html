✅ ICOPAY 統合決済プラットフォームのご案内

ICOPAYは加盟店と単一契約を結んだ統合決済プラットフォームです。個別の決済代行業者（PG）情報は開示されず、すべての決済・精算はICOPAYブランドで統合処理されます。

  • ポータルURL: https://icopay.co.kr
  • 決済URL: https://icopay.co.kr/checkout/{加盟店コード}
  • カスタマーサポート: https://icopay.co.kr

📋 命名原則

ICOPAYは単一APIの背後で複数の決済網を統合するプラットフォームです。本マニュアルの機能（チェックアウト、URL決済、統合取引等）ではICOPAY用語のみを使用します。加盟店・購入者向けの画面とAPIには、個別の決済代行ブランド名を表示しません。

3. API連携（加盟店APIポータル）

加盟店API > 加盟店APIポータル

3-1. 公式連携資料の場所

本社がAPI配備を完了すると、加盟店管理 → 加盟店API が公式のキー・ドキュメント・サンプルです。別途メールやファイル配布は不要です。

項目説明用途
加盟店コード（compId）加盟店識別子APIリクエスト body / クエリ
公開APIベースURLICOPAY APIホストサーバー Base URL
ブローカーシークレットサーバー間秘密キーヘッダ X-Icopay-Merchant-Broker-Secret
クイックスタート・パラメータ表Prepare / buyer / Status 仕様サーバー・フロント開発
ダウンロード資料フロー文書・JSON/PHPサンプル連携実装の参考
⚠️ ブローカーシークレットのセキュリティ警告: クライアント（ブラウザ・アプリ）に露出しないでください。再発行は本社のみ可能です。

3-2. Checkout API（ICOPAY統合）

加盟店API画面に表示されるエンドポイント・表を基準に連携します。

API種別エンドポイント説明
一回払い（準備）/api/middleware/v1/merchant/checkout/prepare決済セッション作成
一回払い（セッション）/api/middleware/v1/merchant/checkout/sessionセッション照会
決済状態照会/api/middleware/v1/merchant/checkout/status決済結果の確認
定期決済準備/api/middleware/v1/merchant/checkout/subscription/prepare定期決済開始
定期決済解約/api/middleware/v1/merchant/checkout/subscription/cancel定期決済のキャンセル
リダイレクト決済/api/middleware/v1/merchant/checkout/redirect/prepareリダイレクト決済
応答の pgVendor は常に ICOPAY です。運用PG名は開示されません。決済画面は /checkout/{compId} または /v1/embed-checkout/{compId} のみ使用してください。

3-3. 連携開発の手順

①本社へAPI配備・ブローカーシークレット発行を依頼
②加盟店APIでキー・クイックスタート・パラメータ表を確認
③加盟店サーバーで Prepare → ブラウザには sessionToken/embed のみ
④サーバーで Status API または Webhook により PAID を確定

4-3. 返金申請の方法

決済管理 > 決済履歴 > 詳細 > 返金申請
①決済履歴から返金する取引を選択 → 詳細を見る
②返金申請ボタンをクリック
③返金金額を入力（全額または部分返金）
④返金理由を入力
⑤返金リクエストをクリックして処理開始
⑥返金完了後、ステータスが返金完了に更新
返金可能条件:
  • 決済成功状態の取引のみ返金可能
  • 決済後の一定期間内（通常90日）のみ返金申請可能
  • 既に返金完了した金額は再返金不可
  • 部分返金は元の決済金額を超えることはできません

6-1. 定期決済状況の照会

状態説明

一時停止定期決済が一時中断された状態

期限切れ定期決済の期間終了
決済失敗決済試行が失敗した状態

6-2. 定期決済の解約処理

①定期決済履歴から解約する定期決済を選択
②詳細画面で定期決済解約ボタンをクリック
③解約理由を入力（任意）
④解約確認 → 即時解約処理完了
解約後、次回請求日に決済は発生しません。現在の請求期間の金額は原則として返金されません（サービスポリシーにより異なる場合があります）。

6-3. 定期決済の詳細履歴

  • 定期決済開始日、次回請求日、累計決済回数の確認
  • 回次別の決済成功・失敗履歴
  • 決済失敗時の再試行スケジュール確認
  • 定期決済金額変更履歴

11. よくある質問（FAQ）

返金申請後、顧客への返金完了までどのくらいかかりますか？
返金申請後の処理は通常、営業日ベースで3〜7日かかります。決済手段（クレジットカード・ウォレット・QRなど）と元の決済日によって異なります。返金処理状況は決済履歴 > 返金タブで確認できます。
APIのブローカーシークレットを紛失・漏洩した可能性があります。再発行できますか？
ブローカーシークレットの再発行は本社のみ可能です。漏洩の疑いがある場合はICOPAY本社へ依頼してください。再発行直後に旧シークレットは無効になるため、サーバー設定を直ちに更新してください。連携仕様・サンプルはログイン後の加盟店API画面で確認します。
定期決済の解約を受け付けました。現在の請求期間分を返金する必要がありますか？
現在の請求期間の返金はサービスポリシーによります。定期決済履歴で対象の定期決済を解約し、必要に応じて決済履歴から当該決済への部分または全額返金を別途申請してください。
精算はいつ支払われますか？精算スケジュールを事前に確認できますか？
精算サイクル（日次・週次・月次）と支払日はICOPAYとの契約条件によります。精算管理 > 加盟店精算履歴で次回精算予定日を確認できます。精算スケジュールの変更が必要な場合はICOPAY担当者にご相談ください。
パスワードを忘れました。どうすれば再設定できますか？
ICOPAYログイン画面のパスワードをお忘れの方をクリックして、登録済みメールアドレスにリセットリンクを受け取ってください。メールにアクセスできない場合はICOPAYカスタマーサポート(https://icopay.co.kr)にご連絡ください。
決済通知（Webhook/Notify）URLはどこで設定しますか？
決済通知URLの設定は加盟店ポータルから直接変更できず、ICOPAYの運営チームが管理します。通知URLの登録・変更が必要な場合はICOPAY担当者にご依頼ください。決済状態のリアルタイム確認は/api/middleware/v1/merchant/checkout/statusで直接照会できます。
チャットボット商品を追加できません。「スロット上限に達しました」というメッセージが表示されます。
契約済みの商品スロット上限に達しています。使用していない商品を無効化または削除してスロットを確保するか、ICOPAY担当者にスロット数の増加をご依頼ください。
決済履歴をExcelでダウンロードできますか？
決済履歴・URL決済履歴・定期決済履歴・精算履歴などの主要な照会画面にCSVエクスポートまたはExcelダウンロードボタンがあります。検索条件を設定してからエクスポートすると、フィルタリングされたデータのみダウンロードされます。
分割払い契約中に顧客が一回次の支払いをしていません。どう対処すれば良いですか？
分割払い管理 > 進捗管理で該当契約の未完了回次を確認してください。その回次の決済URLをコピーして顧客に再送付できます。支払期限を過ぎている場合はメール管理から再送処理を行うか、ICOPAY担当者に延滞処理方法をお問い合わせください。
