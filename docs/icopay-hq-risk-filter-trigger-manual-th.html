1. ภาพรวมปฏิบัติการ

เอกสารนี้อธิบายในมุมปฏิบัติการว่าเมื่อตั้งสวิตช์แต่ละตัวใน「ตัวกรองความเสี่ยง」เป็นเปิดใช้แล้ว ทริกเกอร์ใดทำงานเมื่อใดจริงๆ

  • กลุ่มเป้าหมาย: ผู้ปฏิบัติการสำนักงานใหญ่ · หน้าจอสิทธิ์ M0129 (การตั้งค่าความเสี่ยง)
  • การบันทึกนโยบาย: tb_hq_risk_card_policy (id=1) · ใช้กับทุกร้านค้าทันทีหลังบันทึก
  • การบล็อกก่อนขาย: ก่อนทันทีที่เรียก PG (JPAY·ChillPay·Eximbay ฯลฯ)
  • คูลดาวน์หลังขาย: หลัง JPAY pay_index สำหรับความเสี่ยงสูง·PY0124 (สวิตช์อิสระ)

2. การตั้งค่าความเสี่ยง vs ตัวกรองความเสี่ยง

พื้นที่ทริกเกอร์ผลลัพธ์
การตั้งค่าความเสี่ยง (การจัดการความเสี่ยง)สะสมการไม่สำเร็จของบัตรเดียวกัน (FAIL·ยกเลิก·โมฆะ·ยังไม่ชำระ ฯลฯ)รอขั้น 1–4 · ลงทะเบียนบัตรไม่ใช้งานอัตโนมัติ
ตัวกรองความเสี่ยงรูปแบบ·ความเร็ว·ข้อมูลติดต่อไม่ตรง·ชื่อต้องสงสัย ฯลฯไม่เรียก PG · ยกเลิกระบบ(20) · สถานะความเสี่ยง
สถานะความเสี่ยงร้านค้าโหมดจัดการความเสี่ยงต่อร้าน (HQ / แยก / ไม่ใช้)แสดงค่าเวลารอทริกเกอร์·ลงทะเบียนอัตโนมัติที่ใช้จริง

「ตั้งค่าแยก/ไม่ใช้」ของร้านค้ามีผลก่อนสำหรับการจัดการความเสี่ยง (ทริกเกอร์สะสม) สวิตช์ตัวกรองก่อนขายเป็นไปตามนโยบายสำนักงานใหญ่

3. โฟลว์การประมวลผลทั้งหมด

ผู้ซื้อพยายามชำระเงิน → (การตรวจอื่น: แบรนด์บัตร·นโยบาย ฯลฯ) → หาก【ตัวกรองก่อนขายเปิดใช้=Y】ตรวจรายการ (§5 ลำดับ) → เมื่อฝ่าฝืน: ไม่เรียก PG · ยกเลิก(20) · สถานะความเสี่ยง · แจ้งผู้ซื้อ → เมื่อผ่าน: ขออนุมัติจาก PG → (เฉพาะ JPAY) ความเสี่ยงสูง/PY0124 หลังขาย → คูลดาวน์·สถานะ (เมื่อสวิตช์นั้น=Y)
โฟลว์โฮสต์ (ไม่เก็บหมายเลขบัตร): เน้นอีเมล·โทรศัพท์·ชื่อ·IP·ความเร็วอีเมล หากไม่มีแฮชบัตร ความเร็วบัตรและการไม่ตรงของข้อมูลติดต่อจะข้ามโดยพฤตินัย

4. พฤติกรรมเมื่อ「เปิดใช้」รายการ

เมื่อบันทึกรายการบนหน้าจอเป็นเปิดใช้(Y) ทริกเกอร์ด้านล่างจะทำงาน ไม่ใช้(N) จะข้ามเฉพาะการตรวจนั้น

5. ลำดับตรวจตัวกรองก่อนขาย

เมื่อตัวกรองก่อนขายเปิดใช้=Y โค้ดจะประเมินตามลำดับด้านล่างและหยุดทันทีที่ฝ่าฝืนครั้งแรก

  1. อีเมลผิดปกติ — EMAIL_INVALID
  2. หมายเลขโทรศัพท์ผิดปกติ — PHONE_INVALID
  3. ชื่อ holder น่าสงสัย — HOLDER_NAME_SUSPICIOUS
  4. จำกัดความเร็วบัตร — VELOCITY_CARD
  5. จำกัดความเร็วอีเมล — VELOCITY_EMAIL
  6. จำกัดความเร็ว IP — VELOCITY_IP
  7. ข้อมูลติดต่อผู้ซื้อไม่ตรงกัน — BUYER_*_MISMATCH (อีเมล → โทรศัพท์ → ชื่อ)
① EMAIL_INVALID → ② PHONE_INVALID → ③ HOLDER_NAME_SUSPICIOUS → ④ VELOCITY_CARD → ⑤ VELOCITY_EMAIL → ⑥ VELOCITY_IP → ⑦ BUYER_EMAIL / PHONE / NAME_MISMATCH
หากสวิตช์รายบุคคลเป็นไม่ใช้ จะข้ามเฉพาะขั้นนั้น ตัวอย่าง: ปิดเฉพาะรูปแบบอีเมล → ข้าม ① แล้วต่อจาก ②

6. ผลลัพธ์การบล็อก · การยืนยันปฏิบัติการ

  1. ไม่ส่งคำขออนุมัติไปยัง PG
  2. บันทึกการพยายาม 1 ครั้งในระบบ สถานะยกเลิก(20)
  3. เก็บใน tb_pay_risk_filter_event → การจัดการปฏิบัติการ → สถานะความเสี่ยง
  4. การตอบกลับผู้ซื้อ: ข้อความหลายภาษา · รหัสข้อผิดพลาด PRESALE_RISK_FILTER

หากลูกค้าปกติถูกบล็อก ให้ตรวจ filterCode ในหน้าสถานะ แล้วผ่อนเฉพาะรายการนั้น (ไม่ใช้) หรือปรับหน้าต่าง/จำนวนความเร็ว

7. คำแนะนำปฏิบัติการ · FAQ

รายการแนะนำ
เปิดใช้ตัวกรองก่อนขายเปิดใช้
รูปแบบ·holder·ความเร็ว 3 ชนิดเปิดใช้ · หน้าต่าง 10 นาที / จำนวน 3 ครั้ง
ข้อมูลติดต่อไม่ตรงกันเปิดใช้ (จำอัตโนมัติอยู่ที่แท็บชำระเงิน·URL)
JPAY หลังขาย 2 ชนิดเปิดใช้
  • ปิดเฉพาะบางส่วน: คงตัวกรองก่อนขาย=เปิดใช้ ตั้งเฉพาะรายการที่มีปัญหาเป็นไม่ใช้
  • ปิดทั้งหมด: ตัวกรองก่อนขาย=ไม่ใช้ (รายบุคคลเป็น Y ก็ไม่ทำงาน)
  • ไม่มีธุรกรรมในล็อก PG: มักหมายถึงการบล็อกก่อนขายทำงานตามปกติ
  • จำอัตโนมัติ: ไม่ได้อยู่ใต้「ตัวกรองความเสี่ยง」; นโยบายสำนักงานใหญ่ → ชำระเงิน·URL → ค่าเริ่มต้นการแสดงหน้าต่างชำระเงิน
