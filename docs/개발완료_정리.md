## 1. 구현 완료 기능 요약

### 1.1 본사설정
- **PG사 API 연동**: 목록/저장 API 및 화면 플레이스홀더
- **기본 수수료 정책**: 건당/취소/이용/실패/결제/환불/롤링(%)·롤링일수 조회·저장 (DEFAULT scope)
- **API 구성 세팅**: baseUrl, 인증방식, 타임아웃 조회·저장
- **본사별 권한 세팅**: 목록/저장 API (수수료 설정 권한은 업체 상세에서 설정)

### 1.2 업체관리
- **업체 등록**
  - 상위업체 검색 팝업: 검색 버튼 → 모달에서 `/api/comp/list` 검색 후 행 클릭 시 `parentId`/`parentComp` 설정
  - 본사 정보, 정산 계좌, **정산 기본설정**(출금제한일, 기본/추가 지급한도, 보류율·보류기간, 정산주기 D3~D30·주간, 이체구분, 자동이체최소, 지급보류) 입력
  - 등록 시 `OrgUnit` + `MerchantProfile` + `SettlementSetting` + `MerchantCommissionExtra` 자동 생성
  - 등록 완료 후 **수수료관리** 화면으로 자동 이동, 방금 등록한 업체로 검색
- **업체관리(트리)**: 목록 검색, 등록 버튼 → 등록 화면
- **수수료관리**
  - 목록: 업체코드/업체명/수수료율/적용일 (실데이터 연동)
  - **수수료설정** 버튼: 그리드 1건 선택 후 모달에서 C형(건당/취소/결제/환불/롤링) + A·D·E 일부 저장
  - 저장 시 **수수료 변경 이력**(`tb_commission_history`) 자동 적재
- **업체정보조회**: 목록 검색, 상세(지역본사정보) → 상세 폼에 **수수료 설정 권한**(Y/N) 포함, 수정 저장 시 반영
- **업체변경이력**: API·화면 플레이스홀더

### 1.3 수수료 체계
- **A형(기본)**: 계좌활성화, 연회비, 기술서비스료 — `MerchantCommissionExtra` 저장, 수수료설정 모달에서 연회비 등 입력
- **B형(이벤트)**: 취소/무효/실패/언패이드 — 엔티티 필드 존재, 수수료관리 확장 시 사용
- **C형(서비스)**: 카드수수료, 건당승인수수료 — `CommissionPolicy` (가맹점별 scope 또는 DEFAULT)
- **D형(정산)**: 건당 정산수수료, USDT, FX — `MerchantCommissionExtra`, 건당 정산수수료 모달 입력
- **E형(리스크)**: 환불, 차지백 경고 — `CommissionPolicy.refundRate`, `MerchantCommissionExtra.feeRefund` 등
- **수수료 설정 권한**: `MerchantProfile.commissionConfigAllowed` (Y/N), 업체 상세에서 설정

### 1.4 정산
- **정산 기본설정**
  - 가맹점 등록 시 입력 가능 (출금제한, 지급한도, 보류율·보류기간, 정산주기, 이체구분, 자동이체최소, 지급보류)
  - `SettlementSetting` 엔티티: `withdrawLimitDays`, `payLimitDefault`/`payLimitExtra`, `holdRate`/`holdDays`, `calcCycle`, `transferType`, `autoTransferMin`, `payHoldYn`, `calcExcludeDates` 등
  - 조회/저장 API: `GET/POST /api/comp/settlementSetting`, `GET/POST /api/comp/settlementSetting/save`
- **정산 로직**
  - `SettlementCalcService.execute(fromDate, toDate, merchantId)`: 기간·업체별 거래 조회 → 수수료 차감 → **가맹점별 보류율·보류일**(`SettlementSetting.holdRate`/`holdDays`) 적용 → 롤링 보류·지급액 계산 → `SettlementRun` 저장
  - 정산실행 화면: 정산기간(일자범위) + **업체코드** 필터, 정산실행 버튼으로 `/api/settlement/execute/run` 호출

### 1.5 결제·통보·사용자·리스크
- 결제내역, 결제내역(신), 결제실패, 상계취소, URL간편결제, 현금영수증, 유통망/가맹정산, 환수금, 잔액/미수금, **정산실행**, 정산보류, 결제/현금영수증 통보 URL·전송관리, 사용자관리, 메뉴별항목순서, 리스크 현황 — 메뉴·플레이스홀더 및 기존 API 연동

### 1.6 데이터·시드
- **DataLoader**
  - 관리자 계정(admin/admin1!), 공지 3건, 총본사(HQ01)·테스트가맹점(M001, M002), PG 거래 15건
  - 각 `OrgUnit`에 대해 `MerchantProfile`, `SettlementSetting`, `MerchantCommissionExtra` 없으면 생성
  - DEFAULT 수수료 정책(건당 0, 결제 2.5%, 롤링 5% 180일) 없으면 생성

## 3. 페이지·API 연관성

- **업체 등록** → 저장 시 `parentId`/`parentComp`, 정산 기본설정 파라미터 전달 → `SettlementSetting`·`MerchantCommissionExtra` 생성 → **수수료관리**로 이동(방금 등록 업체 검색).
- **수수료관리** → 업체코드(compId) 기준 목록·상세·저장, 수수료 변경 시 `CommissionHistory` 적재.
- **업체정보조회** → 상세에 정산설정 요약(calcCycle, transferType, holdRate, holdDays, payLimitDefault) 및 수수료 설정 권한 포함, 수정 저장 시 `commissionConfigAllowed` 반영.
- **정산실행** → 정산기간 + 업체코드(merchantId)로 실행, `SettlementSetting`의 보류율·보류일 반영.

## 5. 미구현·추가 확장 시 참고

- **영업일**: 정산일을 “영업일 기준”으로 제한하려면 `SettlementSetting.calcExcludeDates` 파싱 + 휴일 API/테이블 연동 후 정산 실행/스케줄에서 사용 가능.
- **정산주기 D+N 자동 반영**: 현재는 사용자가 정산기간(fromDate~toDate)을 선택. 주기별 자동 정산일 계산이 필요하면 `calcCycle`(D3~D30 등)으로 “정산대상일” 계산 로직 추가 가능.
- **수수료 권한 검사**: 총본사만 허용·본사는 권한 부여된 하위만 등 제어가 필요하면 `CommissionService.save`에서 로그인 사용자 org·`commissionConfigAllowed` 체크 추가.

위 범위까지 개발 완료되었습니다.
