# 서버 환경 전환 체크리스트

로컬 개발을 마친 뒤 **운영(또는 스테이징) 서버**에 반영할 때 순서대로 확인합니다.  
상세 절차는 [배포_가이드_FTP_업로드_및_재시작.md](./배포_가이드_FTP_업로드_및_재시작.md) · [서버_재시작_방법.md](./서버_재시작_방법.md) 를 함께 보세요.

---

## 1. 데이터베이스 (PostgreSQL)

운영 DB는 `application.yml` 기준 **PostgreSQL** 이며 `ddl-auto: validate` 이므로 **스키마는 SQL로 반영**합니다.

1. 아래 파일의 내용을 DB에서 실행 (이미 적용된 경우 생략).
   - `pg-app/src/main/resources/db/V11_notify_env_and_inbound.sql`  
     (`tb_hq_notify_env_config`, `tb_pg_notify_inbound`, `tb_merchant_pg_binding.root_no`)
2. 그 외 마이그레이션 SQL이 있다면 동일하게 순서대로 실행.

---

## 2. 백엔드 (pg-app)

1. 로컬 또는 CI에서 빌드:
   ```bash
   cd pg-app
   ./gradlew bootJar
   ```
2. 생성물: `pg-app/build/libs/pg-app-0.0.1-SNAPSHOT.jar` 를 서버 경로에 업로드 후 **재시작**.
3. 환경 변수 확인 (서버마다 다름):
   - `DB_HOST`, `DB_USER`, `DB_PASSWORD`
   - ChillPay 연동 시: `CHILLPAY_*` 등
4. **CORS**: `application.yml` 의 `app.cors.allowed-origins` 에 **관리자 사이트 도메인**이 포함되어 있는지 확인 (예: `https://icopay.co.kr`, `https://www.icopay.co.kr`).

---

## 3. 프론트 (site)

1. 수정된 `site/` 파일을 FTP로 문서 루트에 업로드 (재시작 불필요).
2. **API 베이스 URL** (`site/js/config.js`):
   - 관리자가 **사이트 도메인**과 **API 도메인**이 같고 Nginx가 `/api` 를 백엔드로 넘기면 `PG_API_BASE` 를 빈 값으로 두는 방식이 맞습니다.
   - API가 **별도 호스트**(예: `api.*`)이면:
     - `config.js` 의 호스트 분기에 해당 도메인을 추가하거나,
     - 브라우저에서 `?api=https://API호스트` 로 한 번 열어 저장하거나,
     - `localStorage.pg_api_base` 를 운영 API URL로 맞춥니다.
3. 배포 후 **강력 새로고침**(Ctrl+Shift+R)으로 JS 캐시를 비웁니다.

---

## 4. 전산 노티 URL (NOTI / 외부 콜백)

1. 관리자 로그인 → **본사설정 → 전산노티·결제환경**.
2. **공개 URL 베이스**에 **인터넷에서 접근 가능한 API 호스트**를 입력합니다.  
   - 예: API가 `https://api.icopay.co.kr` 이면  
     `https://api.icopay.co.kr`  
   - 비우면 “API를 호출한 요청의 Host”로 조합되므로, **외부 시스템(NOTI)이 직접 호출하는 URL**은 반드시 고정하려면 여기를 채웁니다.
3. 표시되는 **노티 수신 URL 전체**를 NOTI(전산노티대상)에 등록합니다.
4. HTTPS 인증서·방화벽에서 **POST `/api/open/pg-notify/{토큰}`** 이 막히지 않는지 확인합니다.

자세한 필드·MID/루트 설명: [전산노티_연동_NOTI.md](./전산노티_연동_NOTI.md)

---

## 5. 배포 후 확인 링크 (연동 확인용)

실제 도메인에 맞게 바꿔 사용합니다.

| 구분 | 예시 URL |
|------|-----------|
| 관리자 로그인 | `https://icopay.co.kr/login.html` |
| 메인 | `https://icopay.co.kr/index.html` |
| API (헬스/문서 등 서버 정책에 따름) | `https://api.icopay.co.kr/` |

---

## 6. 자주 하는 이슈

| 증상 | 점검 |
|------|------|
| 로그인 후 API 401/CORS | CORS 목록, 쿠키/토큰 도메인, `PG_API_BASE` |
| 노티가 안 들어옴 | 공개 URL 베이스, NOTI에 등록한 URL과 토큰 일치, HTTPS/방화벽 |
| DB 오류 (컬럼 없음) | V11 등 마이그레이션 SQL 미적용 여부 |

---

이 문서는 **배포·서버 전환 시에만** 실제 서버 URL을 예시로 사용합니다. 일상적인 개발 문서·코드 주석은 워크스페이스 규칙대로 **localhost** 기준을 유지합니다.
