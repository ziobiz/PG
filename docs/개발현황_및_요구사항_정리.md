# PG 통합관리자 - 개발현황 및 요구사항 정리

> **작성일**: 2025-02-27  
> **목적**: 기존 사이트 분석 + 업체등록/정산 핵심 요구사항 정확한 로직 기록

---

## 1. 기존 사이트 분석 요약

### 1.1 프로젝트 구조

| 경로 | 역할 |
|------|------|
| **pg-app/** | Spring Boot 백엔드 (Java 17, PostgreSQL, Thymeleaf, Spring Security) |
| **site/** | 프론트엔드 SPA (HTML/JS, Bootstrap, 탭 기반) |

### 1.2 조직 구조 (OrgLevel)

```
HEADQUARTERS(총본사) → REGIONAL(본사) → MASTER_DIST(총판) → BRANCH(지사) → AGENCY(대리점) → MERCHANT(가맹점)
```

- `OrgUnit`: parentId로 상위 조직 연결
- `MerchantProfile`: 업체 상세 (연락처, 계좌, settleType, commissionRate 등)
- `SettlementSetting`: 정산 설정 (calcCycle, transferType, holdRate, holdDays 등)

### 1.3 수수료 관련 엔티티

| 엔티티 | 역할 |
|--------|------|
| **CommissionPolicy** | scope=DEFAULT(본사기본) 또는 가맹점코드. perTxFee, cancelRate, usageRate, failFee, payRate, refundRate, feeSettlementPerTx, feeUsdt, feeFx, rollingPct, rollingDays |
| **MerchantCommissionExtra** | A/B/D/E형. feeCancel, feeInvalid, feeFail, feeUnpaid, feeSettlementPerTx, feeUsdt, feeFx, feeRefund, feeChargebackWarn |

### 1.4 업체등록 흐름 (compReg)

- 기본정보 → 본사/총판/지사/대리점/가맹점별 섹션 → 계좌정보 → 출금제한 → 지급한도 → 보류율 → **수수료정책** → 정산방법 → PG바인딩 → 결제통보 URL
- 등록 후 수수료관리 화면으로 이동
- `CompService.registerWithExtra()` → OrgUnit, MerchantProfile, SettlementSetting, MerchantCommissionExtra, CommissionPolicy(가맹점 직접입력 시) 생성

### 1.5 정산 흐름 (SettlementCalcService)

- `PgTrnsctn` (status 10=승인, 20=취소) 기반
- CommissionPolicy로 수수료 계산 (건당, 결제율, 취소율, 환불율, 이용율)
- SettlementSetting.holdRate/holdDays로 롤링 보류
- SettlementRun 저장

### 1.6 다국어(i18n)

- **지원 언어**: 한국어, 일본어, 영어, 태국어, 중국어
- **설계 문서**: [다국어_i18n_설계.md](./다국어_i18n_설계.md)

### 1.7 미구현/플레이스홀더

- 유통망정산내역, 가맹정산내역, 환수금관리, 잔액/미수금관리, 정산보류내역 → emptyPage
- 결제통보 전송·수신 로직 → 미구현
- notify 기반 정산 트리거 → 미구현

## 2. 핵심 요구사항 (정확한 로직)

### 2.1 업체등록

**조직 구조**
```
운영본사 > 본사 > 총판 > 지사 > 대리점 > 가맹점
```
- 가맹점 등록 시 **소속 본사·총판·지사·대리점** 지정
- **소속 이동** 가능해야 함

**등록 시 설정**
- 수수료 및 과금 마감, 정산 주기 등 기본 업체 정보 구성

**수수료 종류 (9가지)**

| 수수료 | 과금 방식 |
|--------|-----------|
| 실패수수료 | 고정 |
| 환불수수료 | 고정 |
| 무효수수료 | 고정 |
| 취소수수료 | 고정 |
| UNPAID 수수료 | 고정 |
| 정산 수수료 | 고정 |
| USDT정산 수수료 | % |
| FX 수수료 | % |
| 차지백 수수료 | **고정 + %** (몇 건까지 고정, 해당 건 이상이면 % 과금) |

### 2.2 수수료 설정 (업체등록 후)

- 업체등록 완료 → **수수료 설정** 화면으로 자동 이동
- 본사·총판·지사·대리점별로 해당 가맹점 결제 시 **받을 수수료** 설정
- **중간 단계(총판·지사·대리점)**: **MDR 수수료 + 건당 수수료만** 입력 가능
- **기타 수수료**(실패/환불/무효/취소/UNPAID/정산/USDT/FX/차지백)는 중간 단계에 **지급하지 않음**
- 각 입력 수수료의 **총액**이 가맹점 결제 금액에서 **마이너스**되어 정산

### 2.3 정산

- **노티 서버**에서 해당 가맹점 거래 수신 → 정산·과금 시작
- 업체등록에서 설정한 수수료 적용
- **정산 주기**에 따른 **정산 마감**
- **정산 리포트** 산출
- 각 가맹점에게 **출금** 가능한 페이지 제공

### 2.4 전체 업무 흐름

```
1. 업체등록
   - 본사/총판/지사/대리점 소속 지정 (이후 이동 가능)
   - 수수료, 과금 마감, 정산 주기 설정

2. 수수료 설정 (등록 후 자동 이동)
   - 본사·총판·지사·대리점별 수수료 설정
   - 중간 단계: MDR + 건당 수수료만
   - 기타 수수료: 중간 단계에 미지급

3. 노티 서버
   - 가맹점 거래 수신

4. 정산·과금
   - 거래 내역 기반 정산·과금 진행
```

## 3. 기존 구현 ↔ 요구사항 매핑

### 3.1 수수료 필드 매핑

| 요구사항 | 기존 엔티티/필드 |
|----------|------------------|
| 실패수수료 | CommissionPolicy.failFee, MerchantCommissionExtra.feeFail |
| 환불수수료 | CommissionPolicy.refundRate(%), MerchantCommissionExtra.feeRefund |
| 무효수수료 | MerchantCommissionExtra.feeInvalid |
| 취소수수료 | CommissionPolicy.cancelRate(%), MerchantCommissionExtra.feeCancel |
| UNPAID 수수료 | MerchantCommissionExtra.feeUnpaid |
| 정산 수수료 | CommissionPolicy.feeSettlementPerTx, MerchantCommissionExtra.feeSettlementPerTx |
| USDT정산 수수료 | CommissionPolicy.feeUsdt, MerchantCommissionExtra.feeUsdt |
| FX 수수료 | CommissionPolicy.feeFx, MerchantCommissionExtra.feeFx |
| 차지백 수수료 | MerchantCommissionExtra.feeChargebackWarn (고정+% 구조 확장 필요) |

### 3.2 보완 필요 사항

1. **차지백 수수료**: 고정 + % (구간별) 구조 → 엔티티/로직 확장
2. **수수료 과금 방식**: 고정 vs % 명확히 구분, UI 반영
3. **레벨별 수수료 설정**: 본사/총판/지사/대리점별 MDR+건당만 → 별도 테이블 또는 구조 검토
4. **노티 기반 정산**: 결제통보 수신 → 정산 트리거 연동
5. **정산 리포트·출금**: 유통망/가맹 정산내역, 출금 처리 화면 구현

## 4. 개발 우선순위

| 순서 | 작업 | 비고 |
|------|------|------|
| 1 | 업체등록 - 조직 소속 지정/이동 | 기존 compReg 확장 |
| 2 | 9종 수수료 스키마 정리 (고정/%/차지백) | CommissionPolicy, MerchantCommissionExtra 확장 |
| 3 | 수수료 설정 - 레벨별 MDR+건당 | 신규 화면 또는 기존 수수료관리 확장 |
| 4 | 노티 수신 → 정산 트리거 | ApiNotifyController, SettlementCalcService 연동 |
| 5 | 정산 리포트·출금 화면 | 유통망/가맹 정산내역, 출금 처리 |
