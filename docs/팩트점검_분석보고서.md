## 2. 기본 제공 소스와의 연동 분석

- **메뉴 구조**: `menu-structure.json` 및 `index.html` 사이드바는 동일한 23개 메뉴(본사설정 4, 업체관리 5, 결제 6, 정산 6, 통보 4, 사용자 2, 리스크 1) 구성.
- **화면 생성**: `screens.js`의 MENU_SCREENS 키와 메뉴 URL 일치 시, 검색폼·그리드·폼이 동적으로 생성됨.
- **API 매핑**: `app.js`의 `doSearch`에서 `pane.getAttribute('formurl')`로 URL을 읽고, 해당 URL에 따라 `PG_API.*` 호출. 매핑된 URL만 검색 시 실데이터 요청.

- 참조 사이트(fxhj.soonpay.co.kr)는 요청 시 타임아웃으로 직접 비교 불가. 문서·기존 요구사항 기준으로 정리.
- **구현된 것**: 본사설정(기본 수수료·API 구성 저장), 업체 등록(상위업체 검색·정산 기본설정)·수수료관리(목록·수수료설정)·업체정보조회(상세·수정·수수료 권한), 정산실행(목록·실행 버튼), 공지·결제내역·업체 목록·사용자 목록.
- **미구현/플레이스홀더**: PG사 API 연동 목록, 본사별 권한 세팅 그리드, 유통망/가맹 정산내역·환수금·잔액·정산보류, 통보 4종, 메뉴별항목순서, 업체변경이력 실데이터, 리스크 현황.

## 7. 6번 항목에 대한 제안 및 조치

### 7.1 즉시 적용한 조치
- **정산실행 버튼**: `app.js`에서 `#exCalcBtn`을 `/calc/exCalcList`(및 `/settlement/execute`)일 때도 정산 실행(settlementExecuteRun)과 연동되도록 바인딩 추가. 이제 정산실행 메뉴에서 기간·업체코드 입력 후 [정산실행] 클릭 시 API 호출 및 그리드 갱신됨.
- **업체 등록·정산설정 저장 시 숫자 파라미터**: 폼에서 빈 문자열이 전달되면 `Integer` 바인딩 오류가 나지 않도록, `ApiCompController`의 `register`와 `settlementSetting/save`에서 `withdrawLimitDays`·`holdDays`를 `String`으로 받아 서비스 호출 전에만 정수로 파싱하도록 수정함.

### 7.2 제안 (우선순위)
1. **업체변경이력 (/comp/compInfoHistList)**  
   - CompService.changeHistory에서 실제 변경 이력 소스(예: CommissionHistory, 수수료/정산 변경 로그 테이블)를 조회하도록 구현.  
   - 또는 OrgUnit/MerchantProfile 변경 시 이력 테이블에 insert하는 로직 추가 후, changeHistory에서 해당 테이블 조회.

2. **정산 관련 목록 (calcList, calcGmList, compPointMngList, balcInfo, payHoldList)**  
   - SettlementRun, RollingReserve 등 기존 엔티티로 조회 API를 구현해 각 메뉴에서 사용하도록 연동.  
   - 유통망/가맹 구분이 필요하면 org_unit 계층 또는 구분자로 필터링.

3. **통보 4종 (noti*)**  
   - URL/전송 이력용 엔티티·테이블 설계 후 CRUD API 구현, 프론트는 기존 notify* API를 그대로 호출하도록 두면 됨.

4. **본사설정 PG사 연동·본사별 권한**  
   - PG사 연동: PG사 마스터 테이블·API 추가 후 pgApiMng 목록/저장 연동.  
   - 본사별 권한: 권한 테이블(본사·메뉴·접근여부) 설계 후 permissionMng 목록/저장 연동.

5. **메뉴별항목순서·리스크 현황**  
   - 메뉴별항목순서: 사용자/메뉴별 그리드 컬럼 설정 저장 테이블·API.  
   - 리스크 현황: screens.js에 /risk/list 정의 추가, doSearch에 매핑(또는 리스크 전용 API) 후 빈 목록이라도 그리드 표시되도록 처리.

### 7.3 현재 상태 요약
- **실데이터 연동 완료**: 공지, 결제내역, 업체 목록/상세/등록/수정, 수수료 목록/상세/저장, 정산실행 목록·실행, 본사 기본수수료·API구성, 사용자 목록, 정산설정 조회/저장.  
- **입력장만·빈 목록**: 6번 표의 1~14. 이 중 **정산실행 버튼**만 코드 수정으로 연동 완료. 나머지는 위 제안대로 백엔드 데이터·API 보강 후 연동 가능.
