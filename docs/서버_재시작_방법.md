# 서버 재시작 방법

---

## 로컬 개발 PC (Windows) - 서버 죽었을 때

로컬에서 개발 중 **서버가 죽었거나**, **포트 8080이 이미 사용 중**이라 재시작이 안 될 때 사용합니다.

### 방법 A: 서버_재시작.bat (권장)

프로젝트 루트에 있는 `서버_재시작.bat` 파일을 **더블클릭**합니다.

- 8080 포트를 사용 중인 프로세스를 자동으로 종료
- 2초 대기 후 서버 실행
- H2 메모리 DB(dev 프로파일) 사용

### 방법 B: 수동으로 프로세스 종료 후 실행

1. **포트 8080 사용 중인 프로세스 확인**
   ```cmd
   netstat -ano | findstr :8080
   ```
   - `LISTENING` 줄 맨 끝 숫자(PID) 확인 (예: 8684)

2. **해당 프로세스 강제 종료**
   ```cmd
   taskkill /PID 8684 /F
   ```
   - `8684`를 위에서 확인한 실제 PID로 변경

3. **서버 다시 실행**
   - `로컬_실행_java.bat` 더블클릭
   - 또는 `pg-app` 폴더에서:
     ```cmd
     java -Xmx512m -cp "gradle\wrapper\gradle-wrapper.jar" org.gradle.wrapper.GradleWrapperMain bootRun --args="--spring.profiles.active=dev"
     ```

### 접속 정보

- URL: http://localhost:8080/login.html
- 로그인: admin / admin1!

### "조회된 데이터가 없습니다"일 때

**dev 프로파일**로 실행 중이라면:

1. **업체관리** 메뉴에서 **[시드 생성]** 버튼 클릭
2. 또는 브라우저에서 `http://localhost:8080/api/dev/seed` 주소 직접 접속

이후 **검색** 버튼을 누르면 레그(계층) 구조로 데이터가 표시됩니다. (업체사용상태는 기본 '전체'로 두세요)

## 원격 서버 (Linux) - 파일 올린 후

FTP로 JAR·정적 파일을 올린 뒤 **pg-app(백엔드)** 을 재시작해야 Java/API 변경이 반영됩니다.

### 이 서버(otlpay) 기준 경로

| 항목 | 경로 |
|------|------|
| pg-app 루트 | `/home/ftpuser/pg-app` |
| JAR | `/home/ftpuser/pg-app/build/libs/pg-app-0.0.1-SNAPSHOT.jar` |
| 재시작 스크립트 두는 위치 | `/home/ftpuser/pg-app/restart-pg-app.sh` (루트에 둠) |

> 다른 서버에서는 경로가 다를 수 있습니다. JAR 위치 확인:  
> `find / -name "pg-app*.jar" 2>/dev/null`  
> `*** System restart required ***` 는 OS 재부팅 권고일 뿐, pg-app 과는 별개입니다.

### DB 비밀번호 필수 (PostgreSQL SCRAM)

`application.yml` 에서 DB 비밀번호는 **`DB_PASSWORD` 환경변수**로만 넘깁니다. 비어 있으면:

`The server requested SCRAM-based authentication, but no password was provided.`  
로 기동이 **즉시 실패(Exit 1)** 합니다.

## 방법 1: 스크립트로 재시작 (권장)

**최초 1회**

1. PC 프로젝트의 `server-scripts/restart-pg-app.sh` 를 FTP로 **`/home/ftpuser/pg-app/`** 에 업로드  
2. SSH:

```bash
cd /home/ftpuser/pg-app
chmod +x restart-pg-app.sh
# PC(Windows)에서 FTP로 올렸다면 CRLF 제거 (없으면 무해)
sed -i 's/\r$//' restart-pg-app.sh
nano restart-pg-app.sh
```

3. 파일 안의 **`DB_PASSWORD`** 를 실제 PostgreSQL 비밀번호로 수정. 필요하면 같은 블록에서 **`DB_HOST`**, **`DB_USER`** 도 서버에 맞게 수정 후 저장.

**재시작할 때마다**

```bash
cd /home/ftpuser/pg-app
./restart-pg-app.sh
```

로그: `tail -f /home/ftpuser/pg-app/pg-app.log`  
기동 완료: `grep Started /home/ftpuser/pg-app/pg-app.log`

### `password authentication failed for user "root"` 가 나올 때

PostgreSQL **DB 로그인 이름**이 **`root`** 로 잡혀 있습니다.  
Linux SSH 사용자(`root`)와 **다릅니다.** DB에는 보통 `postgres`, `pgadmin` 같은 **별도 계정**을 씁니다.

1. **`restart-pg-app.sh`** 에서 `DB_USER="root"` 로 되어 있으면 → 실제 DB에 만든 사용자로 바꿉니다.  
   예: `DB_USER="postgres"` 또는 `DB_USER="pgadmin"`
2. **`DB_PASSWORD`** 는 위에서 적은 **그 DB 사용자의 비밀번호**와 반드시 일치해야 합니다.
3. 서버에 설정 파일이 더 있으면 username 이 덮어쓸 수 있습니다. 확인:
   ```bash
   ls -la /home/ftpuser/pg-app/application*.yml /home/ftpuser/pg-app/config/application*.yml 2>/dev/null
   ```
   여기에 `spring.datasource.username: root` 가 있으면 삭제하거나 올바른 사용자로 수정합니다.

---

### `/bin/bash^M: bad interpreter` 가 나올 때

Windows에서 편집·업로드한 스크립트에 **CRLF 줄바꿈**이 들어간 경우입니다. 서버에서:

```bash
cd /home/ftpuser/pg-app
sed -i 's/\r$//' restart-pg-app.sh
chmod +x restart-pg-app.sh
./restart-pg-app.sh
```

(`dos2unix` 가 있으면 `dos2unix restart-pg-app.sh` 도 동일 효과)

## 방법 2: 명령만 직접 입력

**순서를 반드시 지키세요.** (이미 띄운 뒤 `pkill` 하면 방금 프로세스까지 죽습니다.)

```bash
cd /home/ftpuser/pg-app/build/libs

export DB_HOST=localhost
export DB_USER=pgadmin
export DB_PASSWORD='실제DB비밀번호'

pkill -f pg-app-0.0.1-SNAPSHOT.jar
sleep 3

nohup java -jar pg-app-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod --server.port=8080 >> /tmp/pg-app.log 2>&1 &
```

URL·호스트·DB명이 다르면 전체 URL로 지정:

```bash
export SPRING_DATASOURCE_URL='jdbc:postgresql://호스트:5432/DB이름'
export SPRING_DATASOURCE_USERNAME='유저'
export SPRING_DATASOURCE_PASSWORD='비밀번호'
```

## Java 파일만 수정했을 때 (재빌드 필요)

**Java 소스**를 수정해 올렸다면 서버에서 JAR를 다시 만들거나, PC에서 빌드한 JAR를 다시 업로드해야 합니다.

서버에 Gradle이 있다면 (pg-app 루트에서):

```bash
cd /home/ftpuser/pg-app
./gradlew bootJar
```

이후 **방법 1** 또는 **방법 2**로 재시작.

**site 폴더(HTML, JS, CSS)** 만 수정했다면 빌드 없이 **FTP 업로드만** 하면 됩니다. (pg-app 재시작 불필요)

- 실행 스크립트: `server-scripts/setup-icopay-www-nginx-ssl.sh`

### api.icopay.co.kr 도메인 전체 정리 (DNS → 프록시 → SSL → 검증)

**한 문서로 끝까지:** [api_icopay_도메인_완전설정_가이드.md](./api_icopay_도메인_완전설정_가이드.md)

### api.icopay.co.kr 만 SSL 재설정

api.icopay.co.kr 에서 406 Not Acceptable 이 나오거나 SSL 인증서가 없을 때:

1. `server-scripts/setup-api-nginx-ssl.sh` 를 서버 `/home/ftpuser/pg-app/` 에 FTP 업로드
2. SSH 접속 후:
   ```bash
   cd /home/ftpuser/pg-app
   chmod +x setup-api-nginx-ssl.sh
   sed -i 's/\r$//' setup-api-nginx-ssl.sh
   sudo ./setup-api-nginx-ssl.sh
   ```
3. 스크립트가 HTTP 설정 적용 → Nginx 재시작 → Certbot 설치 → SSL 발급 → 완료

### `https://api.icopay.co.kr/` → Forbidden (권한 없음) / Apache 스타일 403

문구가 **`You don't have permission to access / on this server`** 처럼 나오면, 응답은 **대개 Apache(또는 공유호스팅 기본 vhost)** 입니다. **pg-app(Spring)까지 요청이 안 가는 상태**입니다. (이 프로젝트의 앱은 `/` 접속 시 `login.html`로 리다이렉트하도록 되어 있음)

**확인**

- PC에서: `curl -sI https://api.icopay.co.kr/` → **`Server: Apache/...`** 이면 원인 확정.
- API만 살아 있는지: `curl -sI https://api.icopay.co.kr/api/auth/me` (또는 로그인 API) — **여기는 401/200 등이면** Nginx/프록시는 `/api` 만 넘기고 **`/` 는 Apache가 막는 구성**일 수 있음.

**조치 (택1)**

1. **DNS `api.icopay.co.kr` A레코드**가 **pg-app + Nginx 있는 VPS IP**인지 확인. (다른 호스팅/카페24 IP로 가면 Apache 403이 날 수 있음)
2. VPS에서 **`server-scripts/setup-api-nginx-ssl.sh`** 로 만든 설정처럼 **`/` 전체를 `127.0.0.1:8080` 으로 proxy** 하게 Nginx가 **443을 점유**해야 함. Apache가 같은 서버에 있으면 **443 중복** 시 Apache가 먼저 응답할 수 있음 → Nginx만 443 또는 Apache에서 `ProxyPass / http://127.0.0.1:8080/` 등으로 통일.
3. 당장 쓸 URL: 루트 대신 **`https://api.icopay.co.kr/login.html`** 또는 **`https://api.icopay.co.kr/api/...`** (API 호출용).

설정 예시 파일: `server-config/nginx-api-icopay.conf`

**실제 curl 진단 결과·Apache 프록시 예시:** [api_403_진단_및_Apache설정.md](./api_403_진단_및_Apache설정.md)

### `/login.html` 도 Forbidden (403)

`/`, `/login.html` 모두 같은 원인인 경우가 많습니다.

- **Nginx가 `/api/` 만** `8080` 으로 넘기고, 나머지는 **빈 `root` 디렉터리**로 두면 → 디스크에 `login.html` 이 없어 **Apache/Nginx 가 403** 을 냅니다.
- **조치:** `location /` 도 **`proxy_pass http://127.0.0.1:8080;`** (또는 정적 `site/` 를 `root` 로 두고 `/api/` 만 프록시) 하도록 통일. 예: `server-config/nginx-api-icopay.conf`
- **임시로 앱 화면만 확인:** Thymeleaf 로그인은 **`https://api.icopay.co.kr/login`** (`.html` 없음). SPA와는 화면이 다를 수 있음.
- **배포 JAR:** `pg-app` 빌드 시 **`site/` 가 `static` 으로 포함**되어, 프록시만 맞으면 **`/login.html`·`/index.html`** 이 Spring 에서 나갑니다 (`build.gradle` 의 `processResources`).
