## 1. 리스크설정 (카드 비성공 트리거 · 쿨다운)

### 1.1 목적

동일 가맹점에서 **같은 카드**로 FAIL·취소·무효·미결제 등 **비성공**이 반복되면:

1. **1~4차 대기시간**만큼 JPAY(및 동일 카드 정책이 적용되는) 결제 시도를 **일시 차단**하고,
2. **자동 등록 트리거 N차**에 도달하면 **비활성카드(마스킹)** 에 자동 등록해 **이후 결제**를 막습니다.

관련 구현: `PayCardFailCooldownService`, `HqRiskCardPolicyService`, `PayCardFailOutcomeRules`.

### 1.2 항목 설명

| 화면 항목 | 필드 | 기본값 | 설명 |
|-----------|------|--------|------|
| **위험관리 사용** | `enabledYn` | 사용(Y) | **미사용**이면 본사 정책을 따르는 가맹의 **쿨다운·자동등록 전체가 OFF**. (사전 필터와는 별개) |
| **자동 등록 트리거** | `autoBlacklistTriggerTier` | 4차 | 추적기간 안 **비성공 N회가 완료되는 즉시** 비활성카드 등록. **(N+1)번째 시도부터** 차단 |
| **추적기간** | `trackPeriodMode` | 미사용(NONE) | `미사용` / `일` / `월` / `년` — 비성공 이벤트를 세는 **시간 창** |
| **설정기간** | `trackPeriodValue` | (모드에 따라) | 추적기간이 일·월·년이면 **N일/N월/N년** (1~9999) |
| **1~4차 시간·분** | `tier{N}Hours` / `tier{N}Min` | 아래 참고 | N번째 비성공 직후 적용되는 **대기 시간**(시간 0~72 + 분 0~59) |

**기본 대기시간(합산)**

| 차수 | 기본 | 의미 |
|------|------|------|
| 1차 | 0시간 + **5분** | 비성공 1회 후 약 5분 대기 |
| 2차 | 0시간 + **10분** | 비성공 2회 후 약 10분 대기 |
| 3차 | **1시간** + 0분 | 비성공 3회 후 약 1시간 대기 |
| 4차 | 0시간 + 0분 | 기본 0분(코드상 트리거 미도달·대기 0이면 최소 1분 보정될 수 있음) |

### 1.3 집계 규칙 (무엇이 “비성공”인가)

| 포함 | 제외 |
|------|------|
| 실패(99 등), 취소(20), 미결제·무효 등 **비성공 확정** | **성공(승인)** — 성공 시 누적·대기 **초기화** |
| 동기 PG 응답·노티 확정 모두 반영(동일 건 이중 집계 방지) | **3DS 대기(08)** |
| | CVV·카드번호 **형식/입력 오류** 등 검증 단계 오류 |
| | 이미 쿨다운·비활성으로 거절된 재시도(결제내역에 새 건을 남기지 않는 경우) |

### 1.4 동작 흐름

```
결제 시도
  ├─ 비활성카드(수동/자동)에 있으면 → 즉시 차단 (INACTIVE_CARD)
  ├─ 쿨다운 대기 중이면 → 잔여 분 안내 후 차단 (CARD_COOLDOWN_TIER_*)
  └─ 통과 시 PG 결제
        ├─ 성공 → 해당 카드 실패 누적·대기 초기화
        └─ 비성공 확정 → 실패 횟수 +1
              ├─ 횟수 < N(트리거) → N차 대기시간만큼 blockedUntil 설정
              └─ 횟수 ≥ N → 비활성카드 자동등록 + 이후 시도 차단
```

**자동 등록 트리거 예시 (N=3)**

1. 1회·2회·3회 비성공 완료 → **즉시** 비활성 등록  
2. **4번째** 결제 시도부터 차단  

**추적기간**

| 모드 | 동작 |
|------|------|
| **미사용(NONE)** | 기간 제한 없이 누적(성공 시 초기화). 오래된 실패도 남아 있으면 계속 합산 |
| **일 / 월 / 년** | `설정기간` 창 **밖** 실패 이벤트는 삭제·미집계 |

### 1.5 가맹점별 적용 (본사 vs 별도)

본사 **리스크설정**은 기본값입니다. 가맹(업체관리) **리스크관리 트리거**에서:

| 위험 정책 | 효과 |
|-----------|------|
| **본사정책 따름** | 본사 리스크설정의 대기·트리거·추적기간 사용 |
| **별도정책** | 가맹 1~4차·트리거 우선. 추적기간은 가맹 「기간정책」이 **본사따름/별도/미사용** |
| **미사용** | 해당 가맹 **쿨다운·자동등록 OFF** |

화면 **가맹점 리스크 현황**에서 실효 적용 값·수동/자동 등록 건수를 확인합니다.

### 1.6 비활성카드와의 관계

- 자동 등록된 카드: **운영관리 → 비활성카드등록** (`/ops/inactiveCard`)에서 조회·해지  
- **해지** 시 동일 카드의 실패 누적·대기도 함께 초기화되어 즉시 재시도 가능  
- 등록 구분: **수동**(운영자) / **자동**(트리거) — 현황 표의 수동·자동 건수에 반영  

### 1.7 리스크설정 운영 권장

| 항목 | 권장 | 이유 |
|------|------|------|
| 위험관리 사용 | 사용 | 반복 실패·카드 테스트 억제 |
| 자동 등록 트리거 | 3~4차 | 정상 1~2회 실수는 대기만, 반복은 등록 |
| 1·2·3차 대기 | 5분 / 10분 / 1시간(기본) | 단시간 재시도 억제 |
| 추적기간 | 일 30 등 또는 미사용 | 장기 누적이면 「일/월」 권장 |

## 2. 리스크 필터링 (사전 필터 · JPAY 사후)

### 2.1 목적

**리스크설정(트리거)** 과 별도로, 결제 요청을 PG로 보내기 **전에** 형식·속도·도용 의심을 차단하고, JPAY가 **승인 응답 이후**에만 알려 주는 고위험을 쿨다운·현황에 반영합니다.

| 구분 | 시점 | 대상 | 동작 |
|------|------|------|------|
| **사전(Presale)** | 승인 API 직전 | JPAY·ChillPay·Eximbay 등 평가 경로 | 조건 충족 시 **PG 미호출** + 전산 **취소(20)** + **리스크 현황** 기록 |
| **사후(Postsale)** | JPAY `pay_index` 실패 후 | JPAY | 고위험·PY0124 시 **쿨다운 집계 on/off** + 현황 기록 |

> Eximbay 등 **호스티드(카드번호 미수집)** 흐름: 이메일·전화·성명·IP·이메일 속도는 적용, **카드번호 기반**(카드 속도·연락처 불일치)은 자동 skip.

구현: `PayPresaleRiskFilterService`, `PayPresaleRiskFilterCodes`, `JpayPostSaleRiskCooldownService`.

### 2.2 사전필터 사용 (마스터)

- 항목: **사전필터 사용** (`presaleFilterEnabledYn`)  
- **미사용**이면 아래 개별 사전 필터(§2.3)가 **전부 동작하지 않음**.  
- JPAY **사후 쿨다운** 두 항목은 사전필터와 **독립**(각각 사용/미사용).

### 2.3 사전 필터 판정 순서

먼저 걸리는 **하나**에서 즉시 차단합니다.

```
① 비정상 이메일
② 비정상 전화번호
③ 의심 holder명
④ 카드 속도 제한
⑤ 이메일 속도 제한
⑥ IP 속도 제한
⑦ 구매자 연락처 불일치 (이메일 → 전화 → 성명)
```

### 2.4 항목별 설명

#### 비정상 이메일 (`filterEmailInvalidYn`)

- 형식 위반, 로컬부 2자 미만, 동일문자 반복(3자+), 도메인 `example.*` / `test` / `test.*` 등  
- 이메일이 비어 있으면 검사 안 함  

#### 비정상 전화번호 (`filterPhoneInvalidYn`)

- 숫자만 추출. 7자리 미만·15 초과, 동일 숫자, 연속 증감 8자리+, `000000` 시작/`0000000` 끝 등  
- 전화가 비어 있으면 검사 안 함  

#### 의심 holder명 (`filterHolderNameYn`)

- 선불·기프트·간편결제 표기 명의 차단(부분일치, 대소문자 무시)  
  예: `GIFTCARD HOLDER`, `GIFT CARD`, `PAYPAY USER`, `VPRECA`/`V PRECA`, `MERPAY MEMBER`, `KYASH MEMBER`, `PREPAID MEMBER`, `VANDALE USER`, `BUSINESS CARD`  

#### 카드 / 이메일 / IP 속도 제한

| 항목 | 필드 | 집계 키 |
|------|------|---------|
| 카드 속도 제한 | `filterVelocityCardYn` | 동일 가맹 + 카드 해시 |
| 이메일 속도 제한 | `filterVelocityEmailYn` | 동일 가맹 + 이메일 |
| IP 속도 제한 | `filterVelocityIpYn` | 동일 가맹 + 구매자 IP |

공통 수치:

| 항목 | 필드 | 기본 | 범위 |
|------|------|------|------|
| 속도제한 창(분) | `velocityWindowMinutes` | 10 | 1~1440 |
| 속도제한 횟수 | `velocityMaxAttempts` | 3 | 1~99 |

→ 최근 **창(분)** 안 거래 수 ≥ **횟수** 이면 차단.

#### 구매자 연락처 불일치 (`filterBuyerContactMismatchYn`)

- **동일 카드**의 가장 최근 거래와 이메일·전화·성명 비교  
- 하나라도 다르면 차단(도용 의심)  
- 성명: 성·이름 순서만 바뀐 경우는 동일로 간주  
- 카드번호가 없는 흐름에서는 skip  

**정상 재구매 오탐 완화:** 결제창 **자동기억**은  
**본사정책 → 결제·URL → 결제창 표시 기본값 → 자동기억**  
에서 설정합니다(리스크 필터링 섹션이 아님). 가맹이 「본사설정 따름」이면 이 기본값이 적용됩니다.

### 2.5 JPAY 사후 쿨다운

| 항목 | 필드 | 판정 |
|------|------|------|
| JPAY 사후 고위험 쿨다운 | `postsaleCooldownJpayHighriskYn` | 응답에 HIGH-RISK/고위험 등, 또는 연락처 불일치 계열 |
| JPAY PY0124 쿨다운 | `postsaleCooldownJpayPy0124Yn` | 코드 PY0124 · 「거래를 확인할 수 없음」 계열 |

- **사용**: 해당 실패를 **리스크설정 쿨다운 누적**에 넣고, **운영관리 → 리스크 현황**에 기록  
- **미사용**: 쿨다운 집계에서 제외  

### 2.6 사전 차단 시 운영 결과

1. **PG 미호출**  
2. 전산 **1회 시도 → 취소(20)** (필터 사유 포함)  
3. **운영관리 → 리스크 현황** (`/risk/list`) 이벤트 적재  
4. 구매자 결제창에 **KO/EN/JP/CH/TH** 안내  
5. API: `success=false`, `errorCode=PRESALE_RISK_FILTER`, `filterCode=…`, `txnStatus=20`  

#### 필터구분 코드

| 코드 | 현황 표기 |
|------|-----------|
| `EMAIL_INVALID` | 비정상 이메일 |
| `PHONE_INVALID` | 비정상 전화번호 |
| `HOLDER_NAME_SUSPICIOUS` | 의심 holder명 |
| `VELOCITY_CARD` / `VELOCITY_EMAIL` / `VELOCITY_IP` | 카드/이메일/IP 속도 제한 |
| `BUYER_EMAIL_MISMATCH` / `BUYER_PHONE_MISMATCH` / `BUYER_NAME_MISMATCH` | 구매자 연락처 불일치 |
| `POSTSALE_JPAY_HIGH_RISK` / `POSTSALE_JPAY_PY0124` | JPAY 사후(결제창 사전 차단 아님) |

### 2.7 리스크 현황 조회

- 경로: **운영관리 → 리스크 현황** (`/risk/list`)  
- 검색: 업체코드 · 등록일 · **필터구분**  
- 컬럼: 등록일시 · 업체 · PG · 주문/거래번호 · 필터구분 · 내용  
- 엑셀 다운로드 지원  

오탐이 많은 코드는 해당 필터만 **미사용**으로 완화합니다.

| JPAY 사후 고위험·PY0124 | 사용 |

## 3. 두 영역의 관계 (혼동 주의)

| | 리스크설정 | 리스크 필터링 |
|--|------------|----------------|
| **언제** | 결제 전 쿨다운 검사 + 결제 **후** 비성공 집계 | 결제 **직전** 사전 검사(+ JPAY 사후 분류) |
| **무엇** | 동일 카드 **이력 누적** | **이번 요청**의 형식·속도·불일치 |
| **결과** | 대기 / 비활성카드 | PG 미호출·취소(20)·현황 로그 |
| **스위치** | 위험관리 사용 | 사전필터 사용(사후는 별도) |
| **가맹 별도** | 가능(위험 정책) | **본사 공통**(가맹별 ON/OFF 없음) |

사전 필터로 막힌 취소(20)도 정책에 따라 트리거 누적에 포함될 수 있습니다. 사후 고위험/PY0124는 쿨다운 스위치가 켜져 있을 때 트리거 누적에 반영됩니다.

## 4. FAQ

**Q. 리스크설정만 끄면 사전 필터도 꺼지나요?**  
A. 아니요. `위험관리 사용`과 `사전필터 사용`은 독립입니다.

**Q. 가맹만 리스크(트리거)를 끄고 싶어요.**  
A. 업체관리 → 해당 가맹 **위험 정책 = 미사용**. 사전 필터는 본사 공통이라 가맹만 끌 수 없습니다.

**Q. 정상 고객이 속도제한에 걸려요.**  
A. 리스크 현황에서 코드 확인 후 **창↓ 또는 횟수↑**, 또는 해당 속도 항목만 미사용.

**Q. 연락처 불일치가 잦아요.**  
A. 본사정책 → 결제·URL → **자동기억=사용**, 가맹은 본사따름.

**Q. 차단인데 PG사 로그가 없어요.**  
A. 사전 필터 정상 동작입니다(PG로 안 보냄).

**Q. 비활성 등록 후 풀어주려면?**  
A. 운영관리 → 비활성카드등록 → 해지(사유·OTP). 누적도 초기화됩니다.
