1. 개요 · 적용 지점

리스크 필터는 결제 요청을 PG로 보내기 전에 비정상·의심 요청을 차단합니다. 「리스크설정」 트리거는 통합 매뉴얼 §1을 참고하세요.

영역성격
리스크설정(트리거)비성공 누적 → 대기·비활성 자동등록
리스크 필터링사전 차단 + JPAY 사후 고위험
가맹점 리스크 현황가맹별 트리거 적용 값

필터링은 본사 단위 공통이며 저장 즉시 적용됩니다.

구분시점대상 PG동작
사전승인 API 직전JPAY, ChillPay, EximbayPG 호출 취소
사후JPAY pay_index 후JPAY쿨다운·현황 기록
호스티드(카드번호 미수집): 이메일·전화·성명·IP·이메일 속도만 적용. 카드 해시 기반 필터는 skip.

2. 화면 진입 · 저장

  1. 본사정책 → 수수료·리스크 → 리스크
  2. 「리스크 필터링」에서 사용/미사용·숫자 설정
  3. [저장] → tb_hq_risk_card_policy id=1

권한: 본사권한설정(M0129).

3. 사전 필터 항목

3.0 사전필터 사용

presaleFilterEnabledYn — 미사용 시 개별 사전 필터 전부 OFF. 사후 쿨다운은 독립.

① 비정상 이메일 → ② 비정상 전화번호 → ③ 의심 holder명 → ④ 카드 속도 → ⑤ 이메일 속도 → ⑥ IP 속도 → ⑦ 구매자 연락처 불일치

3.1~3.7 요약

  • EMAIL_INVALID — 형식·로컬 2자 미만·동일문자·test/example 도메인
  • PHONE_INVALID — 7~15자리 외, 동일/연속 숫자, 000000 패턴
  • HOLDER_NAME_SUSPICIOUS — GIFTCARD HOLDER, PAYPAY USER, VPRECA, MERPAY MEMBER 등
  • VELOCITY_* — 가맹 단위, 창·횟수 공통
  • BUYER_*_MISMATCH — 동일 카드 최근 1건과 비교(성·이름 순서 바뀜은 동일)
자동기억: 본사정책 → 결제·URL → 결제창 표시 기본값 (HqApiConfig). 리스크 필터링 섹션이 아님.

4. 속도 제한 · 사후 쿨다운

카드·이메일·IP는 각각 창(분)·횟수를 가집니다. 권장 기본: 카드 10/3, 이메일 30/5, IP 15/10.

항목필드기본
카드 창(분) / 횟수velocityCardWindowMinutes / velocityCardMaxAttempts10 / 3
이메일 창(분) / 횟수velocityEmailWindowMinutes / velocityEmailMaxAttempts30 / 5
IP 창(분) / 횟수velocityIpWindowMinutes / velocityIpMaxAttempts15 / 10
JPAY 사후 고위험postsaleCooldownJpayHighriskYn사용
JPAY PY0124postsaleCooldownJpayPy0124Yn사용

5. 차단 결과 · 코드표

  1. PG 미호출
  2. 전산 취소(20)
  3. tb_pay_risk_filter_event → 리스크 현황
  4. 구매자 다국어 안내 · PRESALE_RISK_FILTER
코드현황 표기

PHONE_INVALID비정상 전화번호
HOLDER_NAME_SUSPICIOUS의심 holder명
VELOCITY_CARD / EMAIL / IP속도 제한
BUYER_*_MISMATCH연락처 불일치
POSTSALE_JPAY_HIGH_RISK / PY0124사후 분류

6. 운영 권장 · FAQ

항목권장
사전필터·형식·holder·속도사용 · 10분 / 3회
연락처 불일치사용 + 자동기억
JPAY 사후사용
  • 정상 고객 차단 → 현황 filterCode 확인 후 완화
  • 일부만 OFF → 사전필터=사용 유지, 항목만 미사용
  • 전부 OFF → 사전필터=미사용
  • PG 로그 없음 → 사전 차단 정상
